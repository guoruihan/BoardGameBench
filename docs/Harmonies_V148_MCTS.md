# V1.4.8：公开信息 MCTS 与搜索策略迭代

2026-10-24；包版本0.4.34。当前交付是已实现并通过小规模检查的研究流程。
尚未进行新的900秒正式配对实验，也没有新的强度提升结论。
V147的十小时窗口已经结束；V148正式长跑的新时长仍待确认。实现和有界预检已获授权。

## 为什么换这一条路线

V147相同16开发环境×双座位：模型83.50（动物11.97、地形71.53），终局habitat
搜索98.69（动物42.84、地形55.84）；stack_finish98.78，无可靠超越原搜索证据。
V147纯模型512新环境×双座位确认：最佳86.17285，普通PPO对照86.12012。
额外专家方法相对普通PPO没有可靠收益，不能把相对旧模型的+0.88归因于专家方法。

原搜索只给最多6个当前候选做完整终局rollout，后面始终使用固定策略。
V148检验：在当前动作之后继续搜索连续决策，能否发现固定后续策略不能兑现的布局。
已有数据只作为初始化，不假设旧PPO critic能够准确评价搜索发现的局面。

## 搜索和信息边界

- 使用原来的精确双人环境、公开双方棋盘/市场/剩余库存、原始最终自身总分。
  不改变规则、结束条件、计分和动作权限，不使用单人转移或真实隐藏牌序。
- 每次模拟从公开库存重新采样未来；行动的下一公开状态分支分别保存。
  树节点不按私有袋子/牌堆索引，也不把不同动作历史的规划器记忆合并。
- 对手使用固定V144模型；优化己方绝对分数，不采用零和取负。
  一位玩家连续拿牌、放资源、放动物时，仍是同一位玩家的价值。
- 混合模型概率、habitat和地形排序；初始最多6个候选，随访问次数逐渐增加，
  所有合法动作都有机会进入树。PUCT比较按150缩放的终局分；日志/Q仍用原始分。
- 默认最多16个己方原子动作深度。跨回合时先模拟冻结对手，新的公开随机结果独立分支。
  不预先承诺一个跨越未知补牌结果的完整宏动作；不宣称有限预算能充分展开所有后续回合。
- `search_mcts`以完整habitat终局rollout评价叶子；`search_mcts_wide`加快候选扩展。
  `search_mcts_value`在深度足够时混合使用已通过预测门槛的价值模型，保留终局rollout。
- 预算按整局累计所有己方决策耗时，最多900秒；超时模拟不回传部分结果。
  保存访问数、候选均值/方差、最大深度、叶子来源、模拟步数和回退次数。

这是已知精确模型上的随机树搜索。当前没有学习环境转移模型，也不是完整照搬围棋AlphaZero。

## 学习目标与保留策略

`v148/data.py`独立重放完整训练轨迹，重建双方持久规划器、C++编码和合法动作mask。
保留以下标签来源，不能互相伪装：

| 数据 | 策略目标 | 价值目标 |
|---|---|---|
| 新MCTS真实决策 | 根访问次数归一化 | 实际对局剩余自身得分/150 |
| V146/V147旧专家决策 | 显式硬动作标签 | 同上 |
| MCTS未完成搜索的回退动作 | 无策略标签 | 同上 |

不把候选估计Q当成真实行为回报，不把旧数据塞进on-policy PPO。
候选Q仍归档供后续诊断。数据按环境整体划分训练/验证，同一环境两座位和重复教师不能跨划分。
新MCTS数据可在策略训练中增加采样比例；旧数据继续保留，不按事后分数筛选轨迹。

四个独立学习分支为访问分布策略学习、带父模型KL约束的策略学习、策略＋价值联合学习、
单独的价值学习。总分模型按完整开发对局选择，初始父模型也参与；回退至第0步不冒充新模型。
单独保存最好的价值模型；它预测剩余得分，搜索中转换为当前得分＋150×预测值，恰好加一次。

价值模型必须在至少8个留出的训练环境上，将MSE降低至少25%，且归一化MSE低于0.02，
才能进入混合搜索。这只是预测门槛，不能替代候选排序和相同实际预算下的对局比较。
不满足门槛就继续完整rollout，不自动调用旧PPO critic。

## 正式流程与资源

复用原CPU/GPU调度器和截止守卫，不依赖外部任务平台。默认两个完整搜索—学习循环：

1. a226用旧240局训练数据拟合两种价值初始化；各实际GPU先通过梯度/恢复/导出检查。
2. b35在4个相同新开发环境×双座位，以900秒比较原rollout、MCTS、宽候选MCTS，
   价值模型符合门槛时加入混合版本。短预检成绩不用于淘汰900秒方案。
3. 两个MCTS候选进入新16环境扩测，报告相对原rollout和纯模型的配对环境聚类区间。
   只有相对原rollout至少+1且描述区间下界>0，才标为搜索改进。
4. 能可靠强于纯模型、且距原rollout不超过4分的MCTS候选，生成32新训练环境×双座位。
   未达到数据质量门槛就保留旧策略和负结果，停止本次后续循环。
5. a226四张卡分别学习四个分支，通过共同开发局选出下一轮学生，再送回b35搜索。
   搜索与GPU学习通过不可变的完成manifest交接；等待数据时不会空跑训练填满GPU。
6. 最后统一新256开发环境选型，再用512新确认环境×双座位验证最多两名模型。
   正式测试集不参与，确认集不参与选型；纯模型与900秒搜索结果分别报告。

资源上限：b35最多49物理核（48worker＋控制器），a226最多57物理核
（4×14分支槽＋控制器），均低于128物理核的一半。GPU仅a226的0–3，独立实验，无DDP。
预算覆盖预检、数据处理、训练、评估、重试和保存；到期守卫请求保存并停止本任务进程树。
GPU成本是分配/进程占用时间，不能解释为实际GPU利用率。

- 重放既有240训练局为15999决策、120环境；此时全部是旧专家标签，不能称为新增MCTS训练数据。
  所有正式新数据将从独立148训练种子产生。
- a226真实A100通过非零梯度、精确下一更新恢复、冻结父模型不变、便携权重一致性和8局完整评估。

## 启动和恢复

配置不自动续用V147的过期窗口。新的时长确认后，显式生成两个节点共用的绝对窗口：

```bash
PYTHONPATH=src .venv-train/bin/python scripts/prepare_v148_window.py \
  --out outputs/v148/<new-run-name> \
  --hours <authorized-hours> --started-unix <authorized-start-epoch> --cycles 2
```

实现/预检已花费的时间应计入这次授权，而非在正式启动时偷偷重置计时。
先检查资源空闲，再分别在对应节点用命名tmux启动；`TASK_RUN`替换为生成目录：

```bash
# b35：进入项目根目录；日志由tee持久保存。
tmux new-session -d -s boardbench_v148_search \
  "bash -o pipefail -c 'PYTHONPATH=src .venv-train/bin/python -u -m boardbench.v148.launch --repo . --role search --config TASK_RUN/search_config.json --out TASK_RUN/search 2>&1 | tee TASK_RUN/search_driver.log'"
# a226：同一个TASK_RUN。
tmux new-session -d -s boardbench_v148_learning \
  "bash -o pipefail -c 'PYTHONPATH=src .venv-train/bin/python -u -m boardbench.v148.launch --repo . --role learning --config TASK_RUN/learning_config.json --out TASK_RUN/learning 2>&1 | tee TASK_RUN/learning_driver.log'"
```

恢复必须在原进程退出、资源空闲、对应阶段及总窗口原截止尚未到期时，使用对应目录冻结源码：

```bash
PYTHONPATH=TASK_RUN/search/source/src .venv-train/bin/python -m boardbench.v148.launch \
  --role search --out TASK_RUN/search --resume
PYTHONPATH=TASK_RUN/learning/source/src .venv-train/bin/python -m boardbench.v148.launch \
  --role learning --out TASK_RUN/learning --resume
```

完成局按哈希校验后复用；不完整局保留后重跑。学习恢复权重、优化器和采样RNG。
`status.json`/`cost.json`属于对应节点；`pilot_N.json`/`expanded_N.json`和`expert_N.json`
属于搜索；`ready_N.json`/`retained.json`/`selection/`/`confirmation/`属于学习。
两边的`summary.json`分别证明各自流程完成，不把“已启动”当作“已涨分”。

方法参考：[AlphaZero](https://arxiv.org/html/1712.01815v1)、
[Information Set MCTS](https://eprints.whiterose.ac.uk/id/eprint/75048/)。
