## Lthroughput：固定16局的批量采样

新编号为 `E00_T16`、`E01_T16`、`E10_T16`、`E11_T16`，各自以相应原始编号为父实验。
网络参数与初始化、输入/动作、真实回报/150、完整局MC和PPO超参数均不变。
只将原本串行采集的16局改成同时推进的固定cohort：全部结束才更新策略，没有自动reset、
未完成轨迹截断、混入旧策略样本或扩大rollout batch。浮点批处理和随机数调用顺序改变，
因此不声称新旧采样器生成逐位一致的随机轨迹；新采样器内部支持精确CPU检查点续训。

环境池可在主进程执行，或使用spawn子进程，每个worker固定一个CPU核；GPU推理集中执行。
公开1346维观测、241维mask、动作与转移统计使用共享缓冲区，环境私有bag/deck/RNG不传给策略。
worker不调用CUDA。结束的槽位不再采样；训练行按原始episode顺序组织，不按结束先后排序。
动作批量传回CPU，log-prob/value留在GPU至采样批结束后统一取回。保留float64概率计算
和1e-4更新前一致性门槛，不同时启用AMP、TF32或更大的更新批量。

吞吐测试入口（先检查资源，选择独立空闲GPU和8个物理核）：

```bash
.venv-train/bin/python -m boardbench.v121.benchmark \
  --out outputs/v121_checks/throughput_UNIQUE --seconds 20 --workers 0 2 4 7 \
  --device cuda --reference-root outputs/v121/factorial_20261004_a
```

每种网络的新旧采样器从同一份已复制/校验的参考权重开始，先完成一次真实更新作warmup，
再测完整采样+PPO更新的实际动作/秒。初始化、warmup与GPU总占用另记，不能冒充零成本。
端到端吞吐不包含checkpoint磁盘写入，正式运行的总占用仍计入保存与重启成本。
`--wait-campaign OLD_ROOT --gpu-index 2`可只在旧批次训练已结束、评测队列排空前的空闲窗口启动；
等待期间不会修改或暂停旧实验，超时失败也不影响旧批次。

加速版正式启动在原launch命令后添加 `--batched --collector-workers N`，N由同机实测选择，
范围0–7，每训练任务总CPU配额仍为8核。重新使用三个种子911/912/913，从头训练并单独保存曲线。
替换前必须完成正确性、真实CUDA更新和吞吐检查，再对旧根目录发出正常停止请求；
所有旧日志、权重、优化器/RNG检查点和源码都保留。

加速版还启用独立评测队列：同一里程碑的12组训练完成后，可以继续训练下一里程碑，
无需等旧checkpoint的开发集评测全部结束。评测始终读取不可变的已保存权重，曲线点仍标记
它自己的动作数/目标/split，不使用“当前正在训练的步数”冒充该点的训练量。
评测积压达到48项时暂缓开启下一里程碑，避免队列无界增长；当前里程碑内已派发的训练仍可完成。
每局评测仍为CPU单线程、3秒，4个worker，共享原本独立预留的8核，不改变最终测试隔离。

## 新划分和评测边界

划分生成器固定seed20261004，从[20000000,30000000)不重复抽样：训练池65536、
开发128、确认256、最终测试512；开发健康子集固定为开发集前32局。
旧测试10000000..10000047显式登记为 `historical_audit`，完全排除出训练。
训练配置把开发/确认合并为训练禁止池，但评测始终按各自名字取原始列表。
划分清单和摘要由每次研究根目录 `plan/splits.json` 固化。

在线统一 CPU 单策略单线程、3秒，使用原 timed_score_v1 的最后已提交局面真实总分。
模型载入/准备时间单列，STOP/超时/失败率、动作数、地形/动物/完成卡和延迟均记录。
正常训练只跑 `development_health` 或完整 `development`；两者分开标记，不能连成同一曲线。
最终 test CLI 必须提供源码/划分/策略哈希匹配的冻结选择，并注明 confirmation 选择规则。
这是一项可信研究流程约束，不是针对恶意 Python 的安全隔离。

旧 PPO INC（seed811/8192局）通过显式冻结权重导入；限时搜索也在新开发集上重测。
它们是固定参考，不是新训练重复。每个新模型的随机初始化权重保留，并在开发健康子集评测，
与训练后结果分开标为 `untrained` / `trained`。

## 持续运行与资源

用户最新授权取消本轮总GPU小时上限，持续运行直到用户停止或出现需处理的异常。
不继承V1.2已到期预算，也不是每卡偷偷重置一个“四小时”。

- b35 的 GPU2–5：每卡最多一个独立训练子进程，每个子进程固定8个不同物理CPU核。
- CPU评测另固定8个物理核，与上述训练配额不重叠，最多4个评测worker。
- GPU0已有别的任务，不使用；GPU1数值异常仍隔离，不通过放宽概率检查启用。
- 每个任务开始前检查空闲GPU，忙卡等待，不驱逐别人的进程。
- 训练与评测均有有限单阶段看门狗；总实验没有小时截止，错误保留证据并停止，禁止自动放宽门槛重试。
- GPU时间为全部训练子进程占用时间之和，包括导入/初始化/保存；CPU评测另计。
  总适应墙钟和启动准备时间单列，不用训练内计时替代总成本。

先到4096真实原子动作做接口/吞吐标定，不排名；然后所有四格×三个种子继续到
0.4M、1M、2M、5M、10M、20M、50M，之后在此次持续运行授权下按两倍增长。
每阶段最多900秒后写完整状态并轮转其它任务，尚未到目标的同配置任务重新排队续训。
**900秒是调度切片，不是学习终止或总预算上限。**
所有保存都在完整局/更新批次边界，实际动作数及超额明确记录；不会虚报精确停在400000步。
真实游戏动作、STOP决策、全部策略决策、模拟动作分开计数；本批纯RL模拟动作为0。

K0低分不淘汰正常路线；预算扩展不改变该编号算法。当前实现持续推进四格，不自动凭早期
分数重写架构或挑选最终赢家。也不自动更新用户网页策略；正式发布须另做确认/冻结测试。
这一机制能持续训练与保存结果，但不能保证最终达到“无限制最优”。

主要文件：

| 文件 | 含义 |
|---|---|
| `allocation.json` | GPU UUID、互斥CPU核组、源码摘要、授权与计时范围 |
| `plan/registry.json` | 不可变实验定义；所有路线初始planned，未实现项明确标记 |
| `status.json` / `outputs/v121/latest_status.json` | 当前活跃任务、队列、累计资源、最后checkpoint |
| `training/*/training.jsonl` | 动作轴/累计训练时间/分项得分/概率检查等 |
| `training/*/final.resume.*` | 每个调度片完整checkpoint、推理权重和摘要 |
| `training/*/latest.resume.*` | 同一片内每16批覆盖一次的故障恢复点；历史阶段终点不覆盖 |
| `learning_curve.json` | 有 split/control 标签的开发集实测点 |
| `evaluations/*/episodes.jsonl` | 全部尝试与回放，失败也保留 |
| `gpu_intervals.json` / `cpu_evaluation_intervals.json` | 实际各次资源分配区间 |

安全停止（不影响其它训练）：

```bash
.venv-train/bin/python -m boardbench.v121.launch stop --root outputs/v121/factorial_UNIQUE
```

控制器停止派发，要求活跃训练在完整批次边界保存，等待正在进行的评测结束。
已保存checkpoint可用低层训练入口续训；整条控制器的崩溃自动重启/旧根目录自动恢复**尚未实现**，
不能直接对旧根目录重复launch。异常后先检查日志，再以新目录显式恢复受影响任务。

低层续训示例（需要该run的冻结源码、相同配置和device字符串）：

```bash
PYTHONPATH=outputs/v121/factorial_UNIQUE/source/src .venv-train/bin/python -m boardbench.v121.training \
  --config outputs/v121/factorial_UNIQUE/plan/configs/E00_911.json \
  --resume PREVIOUS_PHASE/final.resume.pt --out NEW_PHASE \
  --target-actions 2000000 --seconds 900 --device cuda
```

`target-actions`为累计真实动作目标，不是追加动作数；`seconds`为本次片的有限看门狗。
