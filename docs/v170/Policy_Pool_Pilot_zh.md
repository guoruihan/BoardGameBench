# V1.7.0：统一 PPO 历史对手池试跑

本轮将 16 个已交付的双人任务接入**同一个训练方法**。Five Tribes 继续作为
规则覆盖未完成的研究环境，不纳入。Harmonies 也使用通用 candidate actor-critic，
不训练其旧的专用网络、规划器或辅助目标。旧的强策略全部保留。

这是一轮流程与吞吐试跑，不是收敛结论，也不要求新 Harmonies 初始化立即追平旧专用模型。

实际运行见 [2026-11-01 启动记录](Launch_20261101.md)。

## 共同配置

| 项目 | 设置 |
|---|---|
| 网络 | 24 维公开候选特征，64×64 Tanh 编码器，actor 与 pooled critic |
| 输入 | 已有各游戏的公开特征与完整合法候选；保留并披露固定启发式/CEM 先验 |
| 初始化 | 有通用 RL 权重时继续；没有兼容权重时通用零残差 actor＋固定启发式先验 |
| 本轮初始化情况 | 15 个环境继续已有通用模型；Harmonies 初始化通用模型，两组权重相同 |
| 奖励 | 完整比赛胜 +1、平 0、负 −1，中间 0；gamma=1，GAE lambda=0.95 |
| PPO | LR 1e-4、4 epochs、minibatch 128、clip 0.2、梯度范数上限 1 |
| 正则 | entropy 0.01，固定先验 KL 0.01 |
| 采样 | 每批 24 局，6 个 CPU actor；神经策略训练时随机采样，部署评测 argmax |
| 上限 | 每组 1 小时，含启动检查、采样、更新、数据保存与验证；最多 4,096 次更新/约 200 万学习决策 |
| 验证间隔 | 每新增至少 20,000 个 learner 决策；结束前预留快速评测时间 |
| 资源 | 每任务 7 个不同物理核；每节点 8 任务加管理余量共 57 核，且不超过半机 |

Harmonies 的游戏规则、双人局面和原始得分不变；其旧专用模型只作为固定验证面板中的
一个强对手。这次不声称是从旧专用模型继续训练。不同游戏的公开特征仍然具有游戏知识，
因此也不声称无手工先验。

## A/B 区别与比较边界

A 使用旧方法的对手组成：约 25% 当前策略自弈，其余为固定先验/启发式混合。
自弈时两边都是当前 learner，可以采集两边的 on-policy 轨迹。B 每局抽取一个
冻结历史对手，仅采集 learner 一侧的训练轨迹，初始池为共同初始模型的冻结副本。

两组使用相同网络、初始权重、奖励、优化参数、环境 seed 命名空间和资源配额。
**A 的一次更新可能包含更多 learner 决策，不能用同样更新次数或局数冒充相同训练步数。**
逐批记录 learner 决策与总环境动作，试跑优先报告一小时内的完成量和曲线；正式效果对照
需要随后确定共同的 learner 步数预算，本轮不据此宣布 B 更强。

训练和验证使用独立的 53-bit seed 分区，独立训练重复另占 run-seed 位；A/B 刻意
共享环境 seed。不会读旧最终确认分数来挑选父模型：优先使用 V160 开发阶段已选择的
通用模型，Spice Road 在已归档通用模型中采用明确、固定的名称顺序，保留原 CEM 对照。

## 历史池

- 上限 12 个，每局固定对手身份和出招模式。批内概率冻结。
- 50% 均匀抽样＋50% 按 `p*(1-p)` 抽样；`p=(wins+0.5*draws+1)/(games+2)`。
- 每批训练统计衰减 0.95；验证 argmax 战绩不混入训练随机策略战绩。
- 验证节点保留初始、最新、已确认最好、最多两个可靠反制成员，随后按质量和行为差异补位。
- 质量初筛为距面板最好不超过 10 个百分点；在至多 512 个固定公开局面上记录 argmax 动作指纹。
  状态不足时报告实际数量，不补造数据。这里只描述出招差异，不宣称战略风格。
- 轮换抽查两个非活跃成员。快速反制信号需扩展到 128 seed 换位后仍成立，才取得反制保留资格。
- 不删除旧权重；每批保存行为版本和更新后模型，每个验证候选保存完整优化器/RNG/池恢复点。

## 数据、评测与恢复

每批压缩保存所有 learner 的公开 observation、候选动作及 mask、动作下标、实际 log_prob、
value、身份、对手、版本、终止/截断与回报。自然终局才生成终局回报；不完整比赛的整条
learner 序列排除出本轮完整局估计器，但仍完整保存。它不以零值假装截断 bootstrap，
也不把超时或 Jaipur 未决规则算成输；报告完成率，承认排除长局可能造成选择偏差。

固定验证面板通常为共同初始模型、另一个保留策略及启发式。每个对手先跑 32 seed×换位；
有充分时间和正向配对信号时，再对候选与 incumbent 一起跑 128 个开发 seed×换位。
晋升要求完整评测且配对 seed bootstrap 区间下界大于 0；时间不够则保留旧 best，
另保存最新候选。512 seed 的最终确认和三次训练重复不在本轮授权预算内。

逐对手保存胜率、自身/对手得分、实际策略决策耗时及完成状态，置信区间按环境 seed 分组，
保持双方换位的相关性。开发成绩并非独立泛化结论。

```bash
# 只读进度；RUN_DIR 指向实际输出目录。

  --config "$RUN_DIR/runs/toy_battle/B/config.json"
```

解包到独立目录，每个任务命名 tmux，启动前复查 CPU、GPU、已有任务重叠；实际 CUDA
更新与恢复检查通过后才进入训练。外层任务期限提供硬停止，正常 runner 提前保存。

## 实施验证

新增采样分布、历史池保留与去重、seed 分离、换位统计、期限派发、真实 PPO 更新及
精确恢复测试。完整 family 回归通过 519 项；小规模 Toy Battle 闭环完成两轮更新、
两轮历史池验证并正常退出。实际集群任务的启动和早期进度单独记录，不能用单元测试代替。

尚未发生正式参数更新，修复后使用相同初始权重和原绝对截止时间，旧日志不覆盖。
