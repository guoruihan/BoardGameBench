# BoardGameBench：当前游戏设置与变体评测设计

核对日期：2026-11-14。规则核对基线：仓库提交 `cfdd1ef`。

本文前半部分记录**已经实现的规则**，后半部分列出**尚未实现、供下一阶段选择的变体**。
本次只整理文档，没有修改环境、训练模型或恢复实验队列。

目前共有 **17 个双人游戏实现**，其中 **16 个进入冻结联合策略池**；Five Tribes
因少数规则边界未解决，保持研究态。这里的“固定配置”指固定版本、组件范围和规则，
不代表每局地图、发牌、市场或骰子相同。新随机种子和新对手是泛化测试，但不是规则变体。

### 共同接口与解释边界

- **一次 `step` 是一个原子决策，不一定是一整个回合。** 选牌、选位置、支付、
  奖励连锁、弃牌、对手反应可能分别占一次决策。比较交互成本时应同时报告局数、
  游戏回合数和原子决策数。
- **真分数、胜负和训练 reward 分开。** 家族适配器可以返回胜负奖励，不能据此说
  游戏只按胜负计分。反过来，Machi Koro 和 El Dorado 没有官方累计分数；
  Toy Battle 也可能由低勋章的一方攻占总部获胜。
- **观察不含私有模拟器状态。** 私有 snapshot、随机数状态、未来牌序以及对手暗手
  只能由裁判用于恢复和验证。已公开的历史可供推理；“现在没有直接展示”不等于
  “不能从历史推断”。每款游戏的公开／私有字段以对应观察实现为准。
- **完整静态规则也是输入的一部分。** 智能体应能查到固定牌表、图案、地图和计分表；
  仅提供名字或短规则摘要不足以公平测试开发能力。静态组件目录不等于当前暗牌内容。
- **外部截断不是游戏规则。** 时间耗尽、原子决策上限、进程失败和未解决裁定，
  必须分别记录，不能自动记为平局、自然终局，或从总样本中删掉。
- **固定 seed 只固定初始随机来源。** 不同策略可能改变抽牌和随机事件调用顺序，
  因而后续不必看到相同牌。配对 seed 和交换座位有助于比较，不能保证整局随机事件逐次相同。

## 2. 各游戏已经实现的具体设置

### 2.1 Cascadia

**组件与开局。** 基础目录有 85 块普通栖息地板块、5 个三格起始板和 100 枚动物
（五种各 20）。双人每局抽取 43 块普通板块、两个不同起始板；公开市场为四组
“板块＋动物”。每人行动 20 回合，最终各有 23 格。全部动物使用 A 计分卡。

**行动。** 免费拿同一组的板块和动物；支付自然标记可拆开选择，覆盖全部 16 种组合。
市场四只相同动物自动重抽；三只相同可每回合免费重抽一次；自然标记允许重抽任意非空
动物子集。每批替换抽完后立即归还该批移除动物，再检查下一次过量繁殖。
板块须接到自己的版图，但地形边无需匹配才能放置；动物放到类型匹配的空位，也可弃掉。
板块与动物的放置顺序可交换。放到单地形关键板块获得自然标记，新获得的不能在同一放置阶段花掉。

**计分与结束。** 每类地形按边相接的最大连通区域大小计分；双人该地形领先再得 2 分，
并列各得 1 分；剩余自然标记每枚 1 分。动物 A 卡为：

| 动物 | 当前计分规则 |
| --- | --- |
| 熊 | 只数恰好两只的独立相邻群；0/1/2/3/至少4 对得 0/4/11/19/27 |
| 麋鹿 | 划分为互不复用动物的直线组，长度 1/2/3/4 得 2/5/9/13；求最高分合法划分 |
| 鲑鱼 | 先按原版图一次性排除有至少三只鲑鱼邻居的鲑鱼；剩余鱼群长度 1/2/3/4/5/6/至少7 得 2/5/8/12/16/20/25 |
| 鹰 | 没有相邻鹰的数量为 0/1/2/3/4/5/6/7/至少8 时，得 0/2/5/8/11/14/18/22/26 |
| 狐狸 | 每只狐狸按相邻动物种类数得分，同种只计一次 |

总分相同时比较剩余自然标记，仍相同共享胜利。双方版图、市场与公开历史可见；
未来板块顺序、未入局板块身份和 RNG 不可见。动物袋精确余量可由初始供给和公开历史推断，
观察不直接提供全部计数。尚未实现其他动物计分卡、场景、家庭模式和扩展。

依据：[规则与裁定](v160/games/cascadia.md) · [组件表](../src/boardbench/families/data/cascadia.json) · [实现](../src/boardbench/families/games/cascadia.py)。

### 2.2 Calico

**组件与开局。** 固定青色和紫色棋盘，各有 22 格印刷边界及 25 格内部区域；内部包含
三个目标位置、22 个可放拼布的位置。108 块拼布为六色×六图案×三份。固定猫为
Millie（连片 3 格／3 分）、Tibbit（4 格／5 分）、Coconut（5 格／7 分）；
六种图案随机分成每猫两种。每只猫的一个合格连片必须是同一种图案，不能混合该猫支持的两种图案。
每人先从提供的四个目标中选三个并排列位置，然后获得两块暗手；公共市场三块。

**行动。** 每回合从手中放一块到空位，再从市场补一块，最后一次放置也保留补牌步骤。
每人共放 22 块。目标选择、放置、补牌分别形成 API 决策。
同色连片达到三格可拿 3 分纽扣；收齐六色纽扣可拿 3 分彩虹纽扣。
猫按相同图案连片达到其阈值发奖。扩大已获奖连片不会重复领奖；合并连片不抹掉已领取奖励。

**计分与结束。** 六类目标检查周围六格的颜色、图案分布：

| 分布 | 满足颜色或图案之一 | 两者都满足 |
| --- | ---: | ---: |
| 六种各异 | 10 | 15 |
| 3＋3 | 8 | 13 |
| 2＋2＋2 | 7 | 11 |
| 4＋2 | 8 | 14 |
| 3＋2＋1 | 7 | 11 |
| 2＋2＋1＋1 | 5 | 8 |

双满足使用右列，不把两列相加。总分为目标、猫和纽扣之和；平分依次比较猫标记数、
纽扣数（含彩虹），再共享胜利。本人手牌可见，对手暗手隐藏；公开选取的历史仍可用于推断。
未覆盖其他棋盘、其他七只猫、家庭模式。

依据：[规则与裁定](v160/games/calico.md) · [组件表](../src/boardbench/families/data/calico.json) · [实现](../src/boardbench/families/games/calico.py)。

### 2.3 Patchwork

**组件与开局。** 两块 9×9 棋盘，完整 33 块普通拼布、五块 1×1 皮革和首个填满
7×7 区域的 7 分奖励。每人起始 5 纽扣、收入 0、时间位置 0；随机拼布环的中立标记
放在 1×2 拼布之后。先手由评测设置分配。

**行动。** 时间轨落后的一方行动；同格时上层标记行动，因此不保证轮流走。
可以买中立标记之后三块中的一块，支付纽扣、合法旋转／翻面放置，再推进其时间；
也可前进到对手后一格并按实际步数获得纽扣，终点截到 53。
收入触发位置为 5、11、17、23、29、35、41、47、53；皮革位置为
26、32、38、44、50，采用修正版。一次跨越多个事件按轨道顺序处理，刚买拼布的收入立即生效。

**计分与结束。** 双方到达 53 后，得分为 `剩余纽扣 − 2×空格数 ＋ 7×是否取得奖励`；
平分时先到终点者胜。已满棋盘无法放皮革时将该皮革移出游戏，这是已披露的数字版／二级来源裁定。
开局后的棋盘、拼布环、资源和时间轨全部公开；不提供 RNG。未包含 Express、Doodle、Automa。

依据：[规则与修正](v160/games/patchwork.md) · [完整形状、价格、时间、收入](../src/boardbench/families/data/patchwork.json) · [实现](../src/boardbench/families/games/patchwork.py)。

### 2.4 Harmonies

**组件与开局。** 双方使用 23 格 A 面，120 枚地形资源（灰 23、蓝 23、棕 21、绿 19、黄 19、红 15）、
32 张基础动物卡；公开市场为
五组各三枚资源及五张动物卡；最多同时保留四张未完成动物卡。不使用自然精灵。
这里是正式双人环境，区别于早期单人环境和“随机市场对手、固定 13 回合”的训练课程。

**行动。** 每回合必须取一组资源并放完三枚；最多取一张动物卡，可以不取。
取卡、放资源、放动物允许按合法顺序交错；完成动物卡释放未完成卡槽。
堆叠遵守地形层数、支撑组合与动物占位限制；动物按卡片图案放置。
动物一旦放下，即使随后改变相关图案也不移除。动物标记按无限供给处理。
回合结束只补市场空位，不采用单人每轮额外丢弃资源等规则。

**计分与结束。** 地形分加动物卡进度分：树高 1/2/3 得 1/3/7；山高 1/2/3 得 1/3/7，
但需有相邻山；每片至少两格的田地得 5；满足周围至少三种顶层颜色的两层建筑得 5。
A 面河流长度 1/2/3/4/5/6 得 0/2/5/8/11/15，超过六格每格再加 4。
当前实现的河长按水格图中最大最短路径距离加一计算；这不是一般图上的最长简单路径求解。
动物分严格查每张卡的放置进度表，不使用统一“每只动物几分”。

自己回合结束时空格不超过两格，或资源袋不足以补齐市场，触发收尾并保证双方等回合；
恰好用最后三枚成功补齐不提前结束。总分平局比较已放动物数，仍相同共享胜利。
双方棋盘、公开动物卡和市场可见；未来资源／卡牌顺序和 RNG 隐藏。
尚未实现 B 面、自然精灵和扩展。

依据：[双人规则](Harmonies_V140_Duo.md) · [家族适配说明](v160/games/harmonies.md) ·
[32 张动物卡](../src/boardbench/environments/data/animal_cards.base32.v1.json) ·
[原始计分实现](../src/boardbench/environments/harmonies.py) · [当前计分加速路径](../src/boardbench/families/harmonies_kernel.py) ·
[双人实现](../src/boardbench/environments/harmonies_duo.py)。

### 2.5 Century: Spice Road

**组件与开局。** 使用 43 张商人牌（34 张交换、8 张生产、1 张升级）、36 张得分牌。
市场六张商人、五张得分牌，双人金币和银币各四枚。每人起始两张商人牌：生产两黄、
升级两次；先手三黄，后手四黄。香料供给无限，库存上限 10。

**行动。** 四选一：打出商人牌、购买商人牌、休息回收已打牌、支付资源取得得分牌。
买较远商人时向前面每张牌放一枚自选资源，先支付再领取目标牌积存资源。
交换可完整重复多次但至少一次；升级允许使用部分次数；超库存时选择丢弃。

**计分与结束。** 有人取得第六张得分牌时完成当前轮，保证等回合。
得分为印刷分＋金币每枚 3＋银币每枚 1＋剩余非黄色资源每枚 1；平分时后手胜。
本人手牌和已得订单可见，对手相应私有内容不直接展示；公开购买、打牌和得牌历史可供推断。
资源、已打牌及硬币等公开，未来牌序隐藏。未包含 Golem 版、宣传牌或系列组合模式。
零次交换的无操作不列为合法动作。

依据：[规则与边界](v160/games/century_spice_road.md) · [完整牌表](../src/boardbench/families/data/century_spice_road.json) · [实现](../src/boardbench/families/games/century_spice_road.py)。

### 2.6 Jaipur

**组件与开局。** 2019 版 55 张牌：钻石／黄金／白银各六、布／香料各八、皮革十、
骆驼十一。每局发五张，骆驼转到个人驼群；市场初始三张骆驼加两张抽牌。
商品手牌上限七张，骆驼不占该上限。商品筹码价值和三／四／五张出售奖励使用真实多重集。

**行动。** 拿一张商品、拿全部市场骆驼、用手牌／骆驼交换至少两张市场商品，或出售
任意合法数量的同类商品。三类贵重商品每次至少出售两张，其余至少一张；
一次卖至少三张可拿相应暗奖励。交换不能将刚取得的同类商品作为返还。

**计分与结束。** 三类商品筹码耗尽或无法将市场补满五张即结束该局。
卢比为商品筹码、奖励筹码及最多骆驼的 5 分奖励之和；骆驼并列无人得奖。
卢比相同依次比较奖励筹码数、商品筹码数。三者都相同目前标记 `unresolved_round_tie`，
不擅自发印章、继续下一局或视为平局。
胜者获一枚印章，先获两枚赢整场；下一局由上一局败者先手。环境主 `scores` 为印章，
不能把它当作卢比分数。

本人手牌、驼群和奖励值可见；对手手牌、驼群精确数量、暗奖励值和未来抽牌隐藏。
公开动作历史保留。这是有明确未解决极端平局边界的已交付环境，不能写成无条件完整规则覆盖。

依据：[规则与平局审计](v160/games/jaipur.md) · [牌和筹码表](../src/boardbench/families/data/jaipur.json) · [实现](../src/boardbench/families/games/jaipur.py)。

### 2.7 Splendor

**组件与开局。** 原版三级发展牌共 90 张，十位贵族中抽三位；每级公开四张发展牌。
双人每种普通宝石四枚、黄金五枚；起始无牌、无宝石。最多保留三张预订牌，
回合结算后宝石总数上限十枚。

**行动。** 取三种不同宝石（不足三种时按可用种类）、同色取两枚（取前该堆至少四枚）、
预订公开牌或牌堆顶暗牌并在可用时取一金，或购买公开／预订牌。
买牌使用永久折扣和资源支付，黄金可替代任意颜色，包括本来有该色宝石时。
超十枚必须选择退还；符合多位贵族时必须选一位，每回合最多来访一位。

**计分与结束。** 有人达到至少 15 声望后完成当前轮，等回合比较声望；
平分比较已购买发展牌数，较少者胜，再平则共享胜利。
仅在所有正常动作都不可执行时允许强制 pass，并按已有裁定公开保留牌。
双方都持续无动作时缺少已核实终局裁定，外部截断不能改成自然平局。
暗预订牌和牌堆顺序私有；公开预订历史保留。不是 Splendor Duel，也不含扩展。

依据：[规则与裁定](v160/games/splendor.md) · [完整牌表](../src/boardbench/families/data/splendor.json) · [实现](../src/boardbench/families/games/splendor.py)。

### 2.8 Gizmos

**组件与开局。** 原版三级各 36 张，共 108 张装置，另有起始装置。

### 2.9 Machi Koro

**组件与开局。** 2014 基础版，15 类设施共 84 张市场牌、每人四个地标。

### 2.10 Ganz schön clever（Clever）

**组件与开局。** 原版计分纸与黄、蓝、绿、橙、紫、白六颗骰子；双人六轮，
每轮两人各当一次主动玩家，共十二个主动回合。计分格、奖励位置与轮次奖励固定。

**行动。** 主动玩家一个回合最多依次选三颗骰子；选走一颗后，当前点数更低的剩余骰子
移到银盘，再掷仍可用骰子。白色可代替其他颜色；蓝区永远使用蓝＋白点数之和，
不因其中一颗已被拿走而改变。被动玩家通常从银盘选择，只有银盘全部无法填入时才回退到
主动玩家保留的骰子。重掷、`+1` 和奖励连锁有独立时机，必须结算完整；
`+1` 在相应窗口内同一颗骰子只能用一次。第四轮奖励两人都在正常回合之前结算。

**计分与结束。** 黄区完整列得 10／14／16／20；蓝区完成格数查递增表
`0,1,2,4,7,11,16,22,29,37,46,56`；绿区完成数得三角数分；
橙区按格子乘数累计；紫区须严格递增，上一格为 6 时重置该限制。
总分为五区分数之和，再加 `狐狸数 × 五区最低分`。
六轮及所有末尾奖励完成后结算，平分比较最高单区分，再平共享胜利。
双方计分纸、当前骰子和已触发奖励公开，未来随机数私有。
不包含 Challenge 纸、后续 Clever 系列游戏。

依据：[规则与时机](v160/games/clever.md) · [完整计分纸](../src/boardbench/families/data/clever_sheet.json) · [实现](../src/boardbench/families/games/clever.py)。

### 2.11 Five Tribes（研究态）

**组件与开局。** Fakir 基础版；30 块地区随机组成 6×5，90 个米宝每格三个。
22 张精灵、54 张资源牌、12 棵棕榈和 10 座宫殿；市场九张资源、三张精灵。
每人 50 金币、11 个骆驼、两个竞价／行动标记；
双人每轮共四个标记行动，不是每人只动一次。

**行动。** 竞价决定标记顺序；拿起一格全部米宝，沿正交相邻格逐个播撒，
不能立即反向，最后一枚颜色须与终点已有米宝相同。拿走终点同色米宝并结算部落能力；
清空地区时可用骆驼占领，再处理地区、精灵、市场／商品等效果。
具体五族能力、精灵支付与可选时机以完整组件目录为准。

**计分与结束。** 最后一只骆驼落地或无合法播撒触发结束，完成当前轮；
后续能力即使重新产生可走法也不撤销结束触发。分数包括金币、黄色／白色米宝及对应精灵修正、
黄色多数奖励、精灵印刷分、领地、棕榈、宫殿和不同商品集合。
基本黄色每个 1 分、白色每个 2 分、黄色多于对手额外 10 分、棕榈 3 分、宫殿 5 分，
部分精灵改变其中的数值。最终总分并列时共享胜利。

**已知未解决情况。** 竞价时无力支付且零位已满，又不能通过允许的售货补足；
以及 Anun-Nak 需要抽三枚米宝但袋中不足三枚。环境显式保留这两类阻塞，
没有以自创裁定伪装完整实现。双方金币／商品中受规则保护的内容及未来抽取保持隐藏。
本游戏当前不进入正式冻结策略池；应先解决规则边界，再加入正式变体评测。

依据：[规则与阻塞说明](v160/games/five_tribes.md) · [完整组件](../src/boardbench/families/data/five_tribes_base.json) · [实现](../src/boardbench/families/games/five_tribes.py)。

### 2.12 Century: A New World

**组件与开局。** 2019 独立基础模式，棋盘 A1/B1/C1/D1，共 23 个地点。
使用适用的 22 张得分牌、17 块奖励板、10 块探索覆盖板；奖励按 4／3／2／2／2／2
组成六叠，本局用 15 块。每人七名可用、五名尚未解锁的工人；先手三黄，后手四黄；
库存上限十。市场四张得分牌，牌堆顶下一张也公开。

**行动。** 工作或休息。进入空地点支付印刷工人数；进入对手占领地点通常支付其工人数＋1，
对手工人退回；不能进入自己已占地点。Native Help 折扣后至少支付一名。
生产、交易、升级按地点执行；工具生产在地点效果之前处理。
堡垒可取得得分牌、奖励板或两者，个人奖励板最多三块；探索移除覆盖板并向双方开放地点，
不免费再执行该地点。可解锁工人至十二名。休息收回本人已放工人，回合末处理资源超限。

**计分与结束。** 有人取得第八张得分牌后等回合结束；得分为印刷分、奖励板、探索分、
剩余非黄资源每枚 1 分。平局后手胜。工人、资源、已获组件、市场、下一张牌、探索覆盖板及奖励叠顶公开，
未来牌序、奖励叠中尚未露出的板块及本局移除的奖励板隐藏。存在合法循环时不编造固定轮数终局，
由外部预算截断。未覆盖 E1/F1 等其他组合及与系列前作混合模式。

依据：[规则与覆盖](v160/games/century_a_new_world.md) · [地点、牌和奖励](../src/boardbench/families/data/century_a_new_world.json) · [实现](../src/boardbench/families/games/century_a_new_world.py)。

### 2.13 Stone Age

**组件与开局。** 每人五名工人、12 食物、农业 0、无工具和普通资源；人口最多十、农业最多十。
永久工具最多三槽，各槽最高四。36 张文明牌，市场四张；28 栋建筑中随机取两叠各七栋，
即本局 14 栋，其余不入局。先手逐轮轮换。

**行动。** 每轮分放工人、按自选顺序结算本人地点、喂食。双人木／砖／石／金地点每处
只许一个玩家占用，狩猎可共享；村庄三个地点一轮最多占两个。本人不能在同轮再次向已占地点加派。
采集先掷公开骰子，再选工具修正，点数和分别除以食物 2／木 3／砖 4／石 5／金 6 向下取整。
永久工具每轮一次，一次性工具用后消失。建筑允许完整支付选择，文明牌按槽位支付一至四份资源，
可以选择不购买；所有卡片效果和他人参与选择保留。

**计分与结束。** 先取得农业食物再按人口喂食；不足时可用普通资源一比一补足，
或承担该轮一次 −10 分。新增人口当轮也吃饭。
一叠建筑耗尽时完成本轮结算／喂食；下一轮文明市场无法补足时结束。
终局分为即时分＋不同绿色符号集合的平方＋职业卡乘数乘对应人口／农业／工具／建筑量
＋剩余普通资源每份 1 分；剩余食物不计该分。平分比较农业＋工具数值＋人口，再平共享胜利。
对手文明卡受私有观察限制；公开购牌历史可记忆，特殊暗抽牌不泄露身份和即时隐藏得分。

### 2.14 Targi

**组件与开局。** 5×5 布局：16 张边界牌，中央九张牌按五张商品／四张部落交替铺设。
基础牌库含 45 张部落、19 张商品牌。每人三个工人、两个交叉标记，
三种普通商品各两份、黄金一份、四胜利点。个人部落区三行四列，最多保留一张未建部落牌。

**行动。** 轮流放工人在边界，不得占强盗、角落、已有工人或正对对手工人的位置；
己方横纵线交叉在中央形成标记。玩家自选顺序结算边界工人和中央标记，
获取／交换资源、购买或保留部落牌、安排部落行并触发能力。
回合结束普通商品合计上限十、黄金上限三；强盗按轨道移动并在角落执行劫掠。

总分为胜利点、部落牌及能力分；完整一行四张同类型加 4 分，四种各异加 2 分。
平局依次比较黄金、普通商品，再共享胜利。
保留手牌和未来牌序私有；中央替换牌在规定翻面时机前不公开。
Fata Morgana、牌堆回收、额外支付等特殊裁定已有独立说明，不能在变体时无记录地替换。

### 2.15 Dominion

**组件与开局。** 第二版官方 First Game 的十种王国牌：Cellar、Market、Merchant、
Militia、Mine、Moat、Remodel、Smithy、Village、Workshop，各十张。
双人 Estate／Duchy／Province 各八张供给、Curse 十张；Copper 总量 60，
发完起始牌后供给 46，Silver 40、Gold 30。
每人七 Copper＋三 Estate，洗牌后手牌五张。

**行动。** 正常回合从一次行动、一次购买、零金币开始，依次行动、财宝／购买、清理。
牌可增加动作、购买、抽牌、金币，或造成攻击／防御、弃牌、废除和获得牌的独立选择。

平局时完成回合更少者胜，仍平共享胜利。本人暗手可见，对手暗手和未来牌序隐藏；
弃牌顶、打出／获得／废除的公开记录按接口提供，不能索取私有牌序。

### 2.16 The Quest for El Dorado

**组件与开局。** 2017 基础版第一条路线，B/C/N/I/K 五块地图相对组件图的旋转为
2/5/2/2/0 个顺时针六分之一圈，共 185 地形格和三个终点入口。六个障碍中随机用四个。
市场包含全部 18 类各三张，共 54 张；六类起始在售，其余等待市场空位。

### 2.17 Toy Battle

**组件与开局。** Castle Field 官方入门配置：17 个节点、26 条连边、八个地区，

对手手牌身份、暗移除身份及储备顺序隐藏。

## 3. 变体应当测什么

建议把问题定义为：**给定公开的新规则和有限资源，agent 能否开发出适应该规则的策略，
以及相对原版策略提升多少。** 只让智能体逐步调用语言模型玩游戏，可以作为另一个对照，
但不等同于开发、训练和迭代能力。

| 变化类型 | 例子 | 能说明什么 | 不能单独说明什么 |
| --- | --- | --- | --- |
| 实例变化，非规则变体 | 新发牌、新随机种子、新拼布顺序 | 固定规则下的泛化 | 学会适应新规则 |
| 对手变化，非规则变体 | 新 RL bot、搜索 bot、不同风格 | 对手适应与博弈泛化 | 理解新计分或新动作 |
| 官方其他配置 | Harmonies B 面、Cascadia 其他计分卡、另一套 Dominion 王国牌 | 同一游戏家族内的内容迁移 | 这些配置已在当前仓库实现 |
| 自定义数值变体 | 动物分权重、空格罚分、结束阈值 | 目标重估、经济规划、时域适应 | 理解新的动作机制 |
| 自定义结构变体 | 市场规模、合法邻接、额外行动条件 | 重建搜索／模型表示和规则推理 | 与原版仍然同分布、同难度 |
| 组合变体 | 已见过的计分变化＋未组合过的结束变化 | 规则组合泛化 | 仅换测试 seed 就能验证该能力 |

官方配置也需要补齐真实组件和时机；自定义变体必须明确写“benchmark 自定义规则”。
特别是数值修改看起来简单，但改变最优玩法的程度可能很不同，不能预先称作低、中、高难度。

## 5. 建议的第一批：四个游戏、八个单因素变体

先用改动范围小、原版对手和分项分数较完整的游戏验证流程。
以下是**建议草案**；名称中的 ID 尚未注册，数值不是已获实验证据支持的最佳设置。

| 拟议 `variant_id` | 相对当前规则的唯一变化 | 保持不变 |
| --- | --- | --- |
| `harmonies_animal_3_2_v1` | `总分 = 地形分 + 1.5×动物分` | 组件、行动、结束与动物数平局规则 |
| `harmonies_terrain_3_2_v1` | `总分 = 1.5×地形分 + 动物分` | 同上 |
| `cascadia_animal_3_2_v1` | `总分 = 地形区域分 + 1.5×动物分 + 地形多数奖励 + 自然标记分` | 全 A 卡、20 回合、全部合法动作和平局规则 |
| `cascadia_habitat_3_2_v1` | `总分 = 1.5×地形区域分 + 动物分 + 地形多数奖励 + 自然标记分` | 同上；多数奖励不乘系数 |
| `patchwork_empty_1_v1` | 空格罚分由每格 2 改为 1 | 普通收入、时间轨、皮革和 7×7 奖励 |
| `patchwork_empty_3_v1` | 空格罚分由每格 2 改为 3 | 同上 |
| `splendor_target_12_v1` | 首次达到至少 12 声望触发收尾 | 全部供给、贵族、等回合、最终声望及平局规则 |
| `splendor_target_18_v1` | 首次达到至少 18 声望触发收尾 | 同上 |

权重使用精确有理数表示；例如 `地形 + 1.5×动物` 可用 `2×地形 + 3×动物`
作内部比较，展示时除以二，避免浮点误判平局。应同时保留原始地形／动物分，
避免看到加权总分变大就误认为策略更强。

这批能先回答“agent 是否真的根据新目标／时域改策略”。它还不足以覆盖新动作、新卡牌
和新地图的理解，第二批再从 Dominion、El Dorado、Toy Battle 等增加结构变化。
不建议第一天同时扩展所有游戏的全部内容，否则规则验证和策略变化很难归因。

### 最小可执行对照

每个变体保留三类结果，均在**变体裁判**下实测：

1. **冻结原版策略直接迁移。** 不修改模型或启发式，先检查动作与接口兼容，得到迁移基线。
2. **只更新规则感知的参考策略。** 搜索使用新模拟器和新计分；需要时调整启发式评分，
   把这一成本单独记账。它回答“只换目标、不重新开发学习算法能做到什么”。
3. **agent 开发策略。** 给相同公开规则、接口和预先约定的交互／计算资源，
   允许写代码、训练、评测和迭代，最后提交可执行策略。

搜索不能仅在报告时重加权旧终局分，继续用旧目标选动作。
纯 RL 即便能载入旧权重，也可能仍然追求原版目标；这正是需要测量的迁移缺口。

## 6. Agent 评测协议建议

### 6.1 交付给 agent 的任务包

公开一份完整基础规则、一份机器可读差异、组件目录、观察／合法动作说明、示例客户端，
以及提交策略的调用协议。评测 seed、对手私有权重、私有状态和最终测试轨迹不公开。
沿用此前讨论的方向：真实环境通过受控服务访问，开发者可以写自己的近似模型，
但不能通过拿到裁判私有状态绕过交互计数。

每个变体单独发布标识和哈希。下面只是**拟议格式**，当前环境尚不接受这些通用字段：

```json
{
  "game_id": "harmonies",
  "base_config_id": "side_a_base32_no_spirits_duo",
  "variant_id": "harmonies_animal_3_2_v1",
  "variant_rules_version": "1",
  "rule_delta": {
    "terrain_score_weight": [1, 1],
    "animal_score_weight": [3, 2]
  },
  "observation_schema": "base-compatible",
  "action_schema": "base-compatible"
}
```

实际发布还应固定组件文件哈希、终局／平局说明、可见信息、运行器版本和预算。
若改变动作或观察结构，需要新 schema 版本及兼容性说明，不能继续宣称旧 checkpoint 无修改可用。

### 6.2 资源分别计账

- **GT 交互：** reset 局数、原子 step 数、裁判 CPU 时间；若开放 GT 的复制、前瞻或搜索，
  这些调用也计入预算，不能只记主轨迹。
- **开发计算：** CPU 核时、GPU 时、墙钟时间；本地训练与自己实现的模拟器都归到这里。
  每轮及整任务如何限额应在开跑前固定，本文件不设定或恢复新的训练窗口。
- **语言模型调用：** 输入、缓存、输出 token 和实际费用（若可得）单独统计。
  开发 agent 不必每个游戏原子动作都调用语言模型；最终可以提交本地执行的策略。
- **最终部署：** 另设更严格的每局累计决策时间、并行度、内存和可用设备约束。
  900 秒搜索可作为高预算参考，不能与严格短时策略混成同一资源档排名。

应分开报告无训练直接迁移与允许开发／训练后的结果。若同时测“直接 LLM 玩”，
它作为独立赛道报告，不用一条混合排名掩盖资源差异。

### 6.3 环境、对手与分数的比较

开发先用少量相同环境，例如四个 seed、双方换位，看能否运行、是否改变行为及收益方向；
该规模不能证明稳定提升。只对选出的少数最终策略增加独立新 seed 确认，预先固定评测批次。
使用已有证据选对手，不为凑低／中／高三档重新启动大规模搜索矩阵。

最终至少报告：

| 指标 | 用途 |
| --- | --- |
| 胜／平／负及不确定性区间，按对手和座位拆分 | 判断对抗表现，检查先手优势 |
| 官方或变体真实分数、原始分项、分差 | 判断策略改善来源；跨权重变体不直接比较总分大小 |
| 自然结束率、截断／非法动作／阻塞／失败数 | 防止只保留成功局造成偏差 |
| GT 交互量、CPU/GPU 成本、部署耗时、LLM token | 衡量开发效率和最终使用成本 |
| 相对冻结原版策略的变化 | 衡量适应是否有效，而不只是该变体容易得高分 |

原版对手强度和风格标签只能作为挑选起点，**不能直接作为变体标定结果**。
同一个原版高分 bot 可能完全不适应新的动物分、结束阈值或地图。
如果某变体只测到一个弱对手，应如实写出范围，不声称已覆盖强策略。

开发集和正式测试集不混用；开发轨迹可用于训练，测试轨迹不能反馈调参。
要测规则组合泛化，应留出未见过的规则组合；仅在同一变体上留新 seed 测的是实例泛化。
配对统计按环境 seed 聚合，不能把同一局的数百个原子动作当作数百个独立样本。

## 7. 实现顺序与验收边界

复用现有环境、加速器、合法动作和策略池，先做具体变体，不需要先搭一个庞大的通用规则系统。
建议顺序为：

1. **冻结当前原版。** 保存当前配置、组件哈希、代码版本和代表性重放；原 ID 的规则不变。
2. **实现第一批的独立配置。** 将相关硬编码计分／阈值变为有默认值的规则参数；
   为变体注册独立 ID，向 agent 暴露规则差异。
3. **验证差异和等价性。** 默认参数必须复现原状态转移、分数、合法动作与私有信息边界；
   针对每个变化写手工可算局面，检查结束、平局、奖励连锁、动作 mask 和观察一致性。
   加速路径和参考路径必须使用同一变体，避免只改 Python 计分而原生特征／rollout 仍用旧值。
4. **跑最小策略对照。** 检查旧 bot 能否合法执行、新目标是否进入搜索和训练；
   存逐局原始结果和简短结论，再决定是否扩大评测或训练。
5. **形成 agent 任务包。** 在规则验证和最小对照完成后固定公开材料、测试 seed、
   对手、预算和提交接口；再测开发 agent。

现有规则边界要一起保留。特别是 Harmonies 的分叉／环状河流计分语义，应在扩展地形目标
之前用手工棋盘与规则解释核对；Five Tribes 不应跳过未解决裁定；Toy Battle 的标准基地
效果需要先确认连锁时机。解决原规则缺陷属于修正版本，不应伪装成用来考 agent 的新规则。

## 8. 与早期项目的关系

项目早期还包含 MicroTiles、Take It Easy、Harmonies 单人和 RiskCollect 等任务。
本文件聚焦当前 17 款双人游戏，不把这些旧任务计入 17 个环境或 16 个正式对手池任务。

但不是已经完成的通用变体 benchmark。

这次文档提供固定配置清单与可实施的下一步选择。第一批变体、协议参数和实验结果均仍待实现与验证。
