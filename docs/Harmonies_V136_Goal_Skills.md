# Harmonies V136：先教布局执行，再学习选目标

## 问题与边界

V135 sticky 的独立 confirmation512 为 110.9043，继续 PPO 对照 110.5488；配对差 +0.3555，描述性 95% 区间 [-0.2159, 0.9268]。这不足以宣称稳定胜出。V135 的 advice 移除/打乱诊断有下降，但不能代替独立总分证据。

历史 V125 32 环境 ×3 搜索种子、900秒/局的 mixed_compiled 均分 114.8542、动物44.0729；V135 两个 sticky 在相同32环境的诊断均分109.2813、动物23.6563、地形85.625。动物差距并不是等量可加的总分空间：两者地形收益明显不同。历史32环境仅用于解释，不用于本轮选模型。

本轮目标：专家已经展示过的动物布局，能否先变成成熟策略能执行的技能，再用真实总分改进目标选择。不是在线调用 LLM，也不改变规则、计分、信息权限或使用正式测试集。

## 数据与三个起始对照

复用 V132 已验证的240局 train-only 专家公开轨迹，SHA256 `3dd53078fc4250b32afc9a0cf45044275b0060e6bdcaeb9511a609902d29abf1`。从每次实际放动物往前最多16个动作、两回合内截取持续可行的片段；至少含一个待放资源和两个前置动作。目标只含当前已拥有/市场可见的卡、锚点、公开棋盘目标堆叠。回看轨迹得到的目标是弱监督标签，不声称是专家当时的真实意图；不提供未来抽牌或隐藏随机状态。

得到1,687段、15,257个带目标的状态动作对；210环境拟合，另30环境只用于技能诊断。这30环境不是独立RL评测：它们可能已被旧/新PPO使用。以片段均匀、再片段内动作均匀采样，避免长片段支配损失。相同状态可因不同未来完成目标重复出现。

候选覆盖诊断：片段起点中，84.35%的专家目标与现有候选主目标完全相同，87.67%有同卡同锚点候选。这仅描述此截取数据，不是所有高分布局的覆盖率。

所有起始试验固定从 V135 `sticky_a/final.pt` 导入完整模型、PPO Adam 和累计计数；使用A副本惯例，不按本轮确认分数挑父模型。

| 分支 | 初始监督 | 在线阶段 |
|---|---|---|
| control | 无 | 原sticky继续PPO |
| plain | 同一批片段动作，但目标输入是当下启发式目标，不是回看成功目标 | PPO +衰减弱BC |
| skills | 同一批动作，条件是该片段实际完成的公开可行目标 | PPO +衰减弱目标BC |

plain/skills 初始256次更新只调整 adapter/gate，冻结成熟body/actor/critic，使用父策略KL和value约束。随后全网PPO，真实分差/150，gamma=1，完整自然终局；BC权重0.02，在第一阶段4M动作内衰减为0。专家历史未知行为概率不进入PPO比率。

## 执行诊断与条件分支

固定最多24个技能留出训练环境，每个状态2个重新采样的公开条件未来，同时比较：指定专家布局、无初始目标、当前启发式目标。初始目标最多持续两回合，之后所有分支均由同一worker加启发式续玩至自然终局。报告指定动物两回合内完成率及真实终局总分。共用随机种子降低噪声，但不同动作导致消耗顺序不同，不保证抽到相同牌。

第一阶段结束后，按新 development audit512 的固定终点总分选非control分支，保留control。仅当skills被选中、总分不低于control超过1分、且两个训练种子的执行诊断均满足以下条件，追加manager分支：

- 指定目标完成率高于control；
- skills指定目标优于自身无初始目标；
- 指定目标续玩总分不低于control超过1分。

这是探索准入门槛，不是统计显著性结论。门槛不通过就不重复盲目的高层PPO。通过时，manager从第一阶段skills的同一终点出发：在32个技能拟合训练环境上，用**当前worker**为最多8个目标各模拟2个新公开未来；用真实终局Q对原先验进行保守重加权，预训练目标选择器，再训练已有半马尔可夫manager PPO。高预算专家续玩Q不作为当前worker能力标签。正式推理仍只用模型和公开候选，不做终局搜索。

## 评测与预算

新seed区间60M–70M，保持原train/test不变；development curve512、audit512、confirmation512互不重叠。阶段1三组×2种子各新增4M真实动作，阶段2继续control和开发审计胜出者各8M；条件通过才增加两个manager副本。固定终点冻结后统一confirmation512，报告总分、动物分、配对区间与目标移除诊断，不把两个训练种子当1024个独立训练试验。

本轮a226 GPU1–3，每卡最多两个试验；GPU0已有无关gmx，GPU4–7亦不动。阶段1最多43个物理CPU（含controller），阶段2为29或43，低于128物理CPU的一半。预检8核。新任务guard4小时，阶段1每试验4200秒、阶段2 6000秒，确认预留独立时间。预检、数据准备、失败尝试与等待均单独记账后并入；不会续用已到期的V135预算。

## 运行与恢复

输出：`outputs/v136/skills_a226_20261021_a`。主要入口：`boardbench.v136.campaign` / `training` / `preflight`。配置：`configs/v136_a226_goal_skills.json`。

在a226上以命名tmux启动：

```bash
bash tasks/main.harmonies-v136-goal-skills/run_a226.sh preflight
bash tasks/main.harmonies-v136-goal-skills/run_a226.sh launch
# 中断恢复；保留原截止时间，不自动续费或延长：
bash tasks/main.harmonies-v136-goal-skills/run_a226.sh resume
```

启动前必须通过源代码一致的本地测试、实际CUDA、成熟模型概率/梯度和下一批更新恢复验证。`source/`封存本次源码，任务按固定阶段自动继续，`promotion.json`记录数据驱动分支选择；不是后台无限生成新算法的LLM循环。

`stage*/curves.svg`与`curves.json`显示曲线，`results.json`显示每个试验状态，`training.jsonl`保留真实更新日志。每批保留前4局公开计划、动作、真实回报、行为概率，训练数据哈希与专家来源可追溯。`completion.json`和`confirmation.json`是最终完成信号，而非仅看GPU占用。

V135旧汇总仅通过纯聚合修复，保留原`guard_result.json`失败证据和`summary_recovery.json`输入哈希；没有改旧冻结源码、重跑训练或评价。
