# Harmonies 开发资源曲线：第一阶段

目标：测量 Agent 能否把更多开发资源转化为在相同部署限制下的策略能力。不预设单调提高，不按隐藏成绩挑策略。首轮使用自有服务的 GPT-5.6-sol medium；后续按相同任务预算补做 GPT-6-Astra medium，接口配置与凭据不进入 Git。

游戏固定为官方双人 Harmonies：`side_a_base32_no_spirits_duo`（A 面、32 张基础动物卡、无自然精灵）。Known 条件公开规则、组件目录和 SDK，真实环境仅通过受控 GT 服务访问。Agent 从空白目录开发并提交可冻结的策略程序或笔记，不要求提交 RL 权重；本阶段仍禁止额外神经网络训练。测试时使用最后一次成功提交的不可变版本，未提交的工作目录不作为答案。

## 固定实验设计

1. **历史版本曲线**：c6 中 8 次成功提交出现 6 个不同文件哈希，经逐文件核验，实际只有 3 个策略版本；每对差异仅为 manifest JSON 的格式。保留全部哈希映射，仅对语义相同的版本评测一次。版本先后依据成功工具输出，不依据文件修改时间或成绩。旧轮没有每次提交的精确资源日志，因此历史图横轴只标版本顺序，不伪造 CPU/token 时间线。
2. **独立预算实验**：4 档资源，每档从空白目录独立开发 3 次。所有组事先规定，允许主动提前结束；只评测最后有效提交，不按测试成绩选中间版本。模型随机性不保证可复现为完全相同输出，重复实验不等于设置了模型随机种子。
3. **统一评测**：16 个全新校准种子，每个换位 2 场，共 32 局。所有历史版本和新策略共享相同测试序列，统一冻结 legacy RL 对手。部署仍为 L20、2 个固定物理核、每局累计 120 CPU 核秒、20 次模型调用、256K 输入/16K 输出、20 分钟墙钟、8 GiB、GPU=0。程序模式无需调用模型；笔记提交仍可使用同一在线额度。
4. **隔离**：评测信息留在可信侧，不反馈开发 Agent；新开发工作区看不到旧程序、历史成绩、其他组产物或隐藏种子。开发与评测使用不同种子密钥；同一重复编号的不同预算组共享开发种子前缀。正式测试域不参与。

| 开发档位 | 墙钟上限 | CPU 核秒上限 | GT 局数上限 | 生成请求上限 | 输入 token 上限 | 输出 token 上限 |
|---|---:|---:|---:|---:|---:|---:|
| 0.25× | 15 分钟 | 7,200 | 8 | 25 | 500,000 | 64,000 |
| 0.5× | 30 分钟 | 14,400 | 16 | 50 | 1,000,000 | 128,000 |
| 1× | 60 分钟 | 28,800 | 32 | 100 | 2,000,000 | 256,000 |

均为 8 个固定物理核、32 GiB，单次输出上限 8,192、输入预检上限 131,072；每项均为上限而非承诺花费。开发最大合计 22.5M 输入、2.88M 输出、1,125 次生成；部署调用另外计账，固定部署协议不随开发档位扩大。校准、编译和程序实验都使用原计算账本。GT 名额由外部服务可信字段执行，更新显示预算不能改变额度。

这条曲线是**联合开发资源包**的比较，不能据此单独归因 CPU/API/GT 的效果。第一阶段保持原有无 GPU、禁止额外神经网络训练的协议；单项资源消融及开放 GPU 学习属于下一阶段。

## 运行与可靠性

驱动脚本 `scripts/run_harmonies_resource_study.py` 在运行任何评测前写入不可变计划，记录快照、预算、分组、CPU 列表和私有种子的哈希承诺。两个开发槽各使用 8 个不重叠物理核；一个评测槽使用另外 8 核，内部 4 局并行，总分配 24 核，并检查不超过宿主机一半。没有 GPU 任务。新研究有独立 12 小时保护截止，旧轮账本与截止不改变。

历史版本评测与新开发可并行；12 次开发结束后，其最终提交自动入评测队列。失败记录保留，不自动重试生成或整个实验；仅纯 token 预检的网络传输故障允许已验证的有限重试。源代码在服务启动后不应修改。中断阶段不自动重新执行，已完成结果可直接读取。

新开发每次成功提交额外记录可信 `publications.jsonl`：时间、序号、哈希、CPU/墙钟/RSS 采样、模型账户计量。CPU 是采样值；模型用量可能包含尚未结算的预留，需与 pending 状态一起解释，不能冒充最终实际消费。

## GPT-6-Astra 复跑

首轮已经结束，不能用它画完整预算收益曲线：12 次开发中 9 次受 DNS 故障影响，其中 2 次因本地托管任务保存了有效策略，被旧实现误标为完成。旧产物和成绩保留，完整性说明另记在首轮 `integrity_notes.json`。本轮修正分类：模型控制器异常退出且未耗尽模型额度时，即使本地任务成功提交，也保留基础设施失败状态；因额度耗尽退出后继续执行已获准本地任务的行为不变。

新的 `resource_curve_v2_20261116` 协议使用 GPT-6-Astra medium，按上表重新独立开发 12 次，每份有效产物仍评测 32 局。复用首轮开发与评测密钥，并核对原哈希承诺与预算；密钥、旧策略、旧成绩均不向开发 Agent 公开。已经做过的历史策略评测不重复执行。

为减少连接频率，新轮改为一个 8 核开发槽和一个独立 8 核评测槽，共 16 个物理核。所有任务的出站请求共用最少 3 秒的发起间隔，包括 token 预检、生成和已有的有限预检重试；等待计入原请求截止及任务墙钟。这是请求发起限速，不是网络并发数或模型推理耗时保证。遇到基础设施故障后停止派发新任务，保存 `paused.json`，已在执行的任务仍受原预算控制；不自动重启整轮或重试生成，也不额外循环调用模型探测健康状态。

本轮保持独立 12 小时外层截止。单开发槽下，全部开发都耗满墙钟需 11.25 小时，评测可与下一次开发重叠；若达到总截止，剩余任务如实记为未运行。该轮同时改变了模型、运行时段和请求调度，不能把成功或失败单独归因于模型，更不能把 DNS 故障解释为模型推理失败。

## 输出与解释

- `preregistered_plan.json`：预注册设计；私有 seed keys 和 worker 配置另存受限目录。
- `study_summary.json`：历史版本、每档每次独立开发的进度和成绩，以及实际开发资源。
- 每任务 `experiment/results.jsonl`、`summary.json`、GT 和模型账本、冻结提交及 source archive。
- `score_curves.png`：结束后生成的历史版本与资源档位散点图；每个独立开发结果单列，不只画最大值。
- `resource_audit.json`：所有子任务已计量费用；工程实现会话、测试/安装和可信服务 CPU 仍按已有审计边界单独说明。

报告胜率、自然终局均分、失败率、随机接管比例和提交成功率。自然终局均分是条件均值，必须伴随完成数；无有效提交不能被悄悄排除或当成一场真实零分对局。每档只有 3 次开发、32 场评测，属于校准而非稳定排名。没有观察到提高或出现退化，也都是有效结果。预算不足或基础设施失败时不宣称全组完成。
