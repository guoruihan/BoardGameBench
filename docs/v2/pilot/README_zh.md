# Harmonies 原生 Codex 开发试跑

本轮测量在有限 GT 对局、模型调用和本地计算内，自主形成可复用笔记或程序的能力。参与者是干净沙盒中的原生 Codex 0.167.0 / GPT-6-Astra medium；基础设施实现会话不是参与者。提交可只有笔记，不要求 RL、模型权重或搜索程序。

首轮已完成：[结果、配置问题与完整资源审计](Results_20261115_zh.md)。c4 独立配对批次 20 局全部自然结束，开发后程序 10 胜、均分 90.7；无前期开发对照 0 胜、均分 32.5，但有 67.07% 本方动作随机接管，不能视作纯模型棋力比较。

逐步过程见 [Agent 开发过程记录](Development_Walkthrough_20261115_zh.md)：从读规则、编写搜索器、自建模拟器到动物终局分配，以及最后封装未赶上预算的证据。

当前配置 `pilot_v2_20261115_c4`：Known 双人 Harmonies，冻结 `legacy` RL 对手；默认开发一次，最多 10 局，随后同一提交在 L10/L20/L40 各 5 个新校准种子×换位，并补 L20 无开发对照，共 40 场测试。四路并行使用独立物理核对。开发、验收、校准、正式种子有不同域；本轮不运行正式排名、Unknown、900 秒搜索或其他游戏。

## c5：托管任务与一次提交

新一轮使用 **GPT-5.6-sol medium**，协议 `pilot_v2_20261116_c5`。从空白工作区重新开发；不继承 c3/c4 程序、会话或开发轨迹。固定预算、Known 规则、冻结 RL 对手和默认 40 场校准设计不变，模型与交付机制同时变化，因此不能把两轮分差仅归因于模型。旧成绩与成本保留。

开发 SDK 新增：

```python
import jobs
job_id = jobs.start(["python3", "finalize.py"])
print(jobs.status(job_id))
print(jobs.output(job_id, stream="stdout", offset=0))
```

任务由同一 bubblewrap 沙盒的 PID 1 启动，是 Codex 的兄弟进程。队列、日志和控制服务保留在沙盒外；管理事件通过内核提供的进程身份验证。模型控制器退出后停止接收新任务和模型生成，已提交任务继续运行，直到全部结束或原有预算到限；不增加预算、不自动重试、不由运行器修复或挑选策略。普通 CLI 工具命令仍不保证在 CLI 退出后存活，需显式使用 `jobs.start`。每个任务的 stdout/stderr 最多各保留 4 MiB。

在封装脚本中，先编译和最小运行检查，再执行：

```python
import submission
submission.publish(directory="candidate", entrypoint="play.py")
```

此操作安全复制目录、检查入口与清单，并在同一锁内原子更新最新提交。入口为 Python 或可执行文件；指定入口时自动生成必要的清单字段与默认说明。省略入口则使用原清单，仍允许仅交付笔记。检查不执行策略、不读取隐藏测试。失败保留上一份提交；后续修改工作区不影响快照；冻结和提交互斥。耗时报告不是提交前置条件。旧 `checkpoint/register_program` 保留兼容，其中注册程序接管与冻结评测入口不是同一概念。

并行任务与控制器共用固定核、整棵进程树 CPU/RSS/墙钟账本；控制服务处理 CPU 也累计计入。到限终止整个沙盒并核验清理，保留最后成功版本。仍属于采样监控后终止，不是内核硬限额；进程崩溃后的任务不自动重启。运行记录包括任务入队、启动、控制器退出、任务退出码/信号、提交时间和冻结事件。

真实原生验收 `managed_acceptance01`：只允许一次生成，下一请求因调用额度返回 429，CLI 退出码 1；任务在 CLI 退出 **11.32 秒后**完成原子提交，最终退出码 0，清理通过。托管任务完成了 5 个真实合法动作；模型消耗 1 次、9,521 输入、146 输出 token。另一次连通性探针消耗 11 输入、5 输出，两者均独立计账，不作为正式策略成绩。

复跑使用上面的通用启动命令，追加 `--model-id gpt-5.6-sol --protocol-version pilot_v2_20261116_c5`；私有路由中的模型必须一致。用 `--managed-acceptance` 可重现一调用额度的生命周期验收，需全新输出目录。新正式复跑在验收后建立独立截止时间；不重置任何旧账本。

## 校准修订

初稿每请求输入上限 32,768。真实原生 CLI 验收显示，工具定义由新版 Codex 放在 `additional_tools` 输入项，上游计数器忽略该项：一次预估 5,756，实际 10,784；25% 余量仍不足，网关正确冻结了账户。修订为**把完整实际请求序列化后，仅在预检时作为文本计数**，实际生成请求保持不变。保留上游计数来源、完整计数材料、预留与结算记录。

完整序列化预检较保守：读取规则和静态目录后的请求在原 32K 上限被拒绝。因此 c1 统一将单请求上限提高到 **65,536**，保留了 20,000 自动压缩阈值。真实开发随后暴露反复读代码即压缩的问题：62 次生成中发生 17 次压缩，仅完成一局开发比赛（87:82），尚无有效检查点或独立测试。通过可信网关停止这一配置试跑，保留全部账本和代码，不将其记为策略测试成绩。

**c2 将自动压缩阈值改为 32,000**，单请求 65,536 与单次开发/测试的累计额度保持不变；补充 `python` 指向系统 Python 3.8 的别名，并修复开发期额度耗尽后的注册程序接管。重新从空白工作区独立开发，不继承 c1 的程序或对局。两版成本分别列出并合计，总八小时截止不延长；此为配置校准后的整套重跑，不是按测试输赢补局。c1 已耗费 62 次生成、1,084,392 输入、49,806 输出 token、1,229.42 秒活跃墙钟、30.13 核秒。c2 对开发后测试与无开发对照统一生效，旧试跑证据保留。

c2 在 26 次生成后遇到保守预检上限，正常保留 `no_valid_submission` 结果：最后一次成功请求的实际输入为 29,201；后续完整序列化计数为 55,913，预留 70,148，超过了 65,536。未保存检查点、未启动测试；开发一局 83:91，仅作配置诊断。消耗 610,587 输入、20,485 输出 token、570.30 秒活跃墙钟、237.33 核秒。

**c3 保留 32K 自动压缩，将单请求保守预检上限设为 131,072**，单次任务累计额度不变，再从空白开始。这个阈值针对包含不透明推理项和工具结构的序列化预检，并不表示模型每次实际消耗 128K；报告以实际 usage 为准。c1/c2 成本都保留并单列，不按其局面成绩挑选程序或继承轨迹。

输入计数上游明确标为 `local_estimate`，网关预留估算值×1.25+256，并按实际 usage 核账；低估、未知 usage 或超额冻结账户。**这是保守预检加实际计量，不能宣称精确的输入 token 硬限制。** 缓存输入包含在输入总数，推理包含在输出总数，不重复加算。请求数与 GT 名额持久强制限制；输出上限由请求参数控制并核对 usage。断流不退还未知消耗，不自动重试生成。

**c4 修复超时后的结算衔接。** c3 的程序部署三档均完成 10 局、8 胜 2 负、均分 97.8:73.6；但无开发对照暴露了真实原生 CLI 的单步超时路径：控制器被终止后，上游请求还未结算，立即续会话触发 `account_inflight`，断开流又可能使 usage 未知。队列在 7 场受影响对照后自动停止，另外 3 场未启动。这不是有效的“无开发胜率为零”证据；原记录与成本保留。

c4 在下游断开后继续读取**原有**生成直到 usage 终结事件或原请求截止，不重发生成、不延长请求时限。外部运行器等待预检和 pending 请求结算后才恢复同一会话，等待计入原墙钟账本；未知 usage 或冻结状态直接归为基础设施失败。另提供显式冻结提交评估入口，以同一提交、全新种子建立独立对照批次，不覆盖旧失败局或重置旧预算。本轮追加批次仅为 L20 开发后与无开发各 10 局，不再开发或选择策略。

真实原生超时续跑验收 `timeout_resume_gate03` 已通过：在第一条生成 pending 时终止控制器，结算后恢复同一会话、同一 GT 与账本，恢复后完成真实动作；6 条生成全部结算、未知 usage 为 0、无 `account_inflight/429`。其中 21.85 秒结算等待已包含在 61.63 秒活跃墙钟内。两个先前启动检查失败均发生在账户/对局创建前、没有生成请求，证据保留。

## 固定预算

| 项目 | 开发 | 每场测试 |
|---|---:|---:|
| GT | 最多 10 局、同时 1 局 | 固定 1 局 |
| 模型生成 | 100 | L10/L20/L40：10/20/40 |
| 累计输入 token | 2M | 128K/256K/512K |
| 累计输出 token，含推理 | 256K | 8K/16K/32K |
| 单请求输入预检 | 131,072 | 131,072 |
| 单请求输出 | 8,192 | 4,096 |
| 活跃墙钟 | 2 小时 | 20 分钟 |
| CPU | 8 个固定物理核，57,600 核秒 | 2 个固定物理核，120 核秒 |
| 内存 | 32 GiB | 8 GiB |
| GPU | 无设备访问 | 无设备访问 |

本轮总工程与实验截止时间另设，先到者停止。GT/对手与网关属于可信进程，资源单列；等待它们时未暂停 Agent，所以仍计活跃墙钟。模型额度耗尽，可在剩余本地额度内继续注册程序；无控制器时随机合法代走并记录。CPU/整局时间耗尽或崩溃计失败，不免费补完，不按局面部分分数计算正常均分。

## 隔离和恢复边界

- bubblewrap 限定文件、PID、网络和设备；只挂只读公共 SDK/规则、显式运行依赖和可写当前工作目录。没有仓库、对手权重、个人历史、外部网络或真实上游 key。
- 原生 CLI 内部使用 `danger-full-access`，权限边界由外层 bubblewrap 和 seccomp 提供；不代表宿主机全访问。保留本地 wrapper，但不挂其个人配置来源。
- 外部账本记录累计子进程 CPU、RSS 和墙钟，超额杀进程树，验证无遗留。CPU/RSS 是采样监测，非 cgroup 内核硬配额；自动回收子进程可能漏计，RSS 会重复计算共享页并漏瞬时峰值/页缓存。报告采样间隔、实际采样缺口、超额和清理延迟。
- 检查点用逐级 `dirfd/O_NOFOLLOW` 复制至可信目录后才校验；限制 64 MiB、10,000 项，拒符号链接/设备/套接字。只检查格式和依赖，不评估策略；冻结最后有效提交，不挑隐藏测试最高分。
- 开发续会话保留原预算；最多连续两次无文件/GT/提交进展的固定提示恢复。测试每局全新工作区/会话，局内可有固定续跑，不把上一局修改带入下一局。
- 可信服务中断不自动重放活动对局。状态、账本、提交和失败证据可恢复检查；这不等于允许无损恢复已丢失的 GT 状态。

## 启动与产物

从项目环境运行；用环境变量 `BOARDBENCH_CODEX_WRAPPER` 指定经核验的本地启动器，私有路径由本机配置提供。私有上游 JSON 只放 Git 忽略目录或仓库外，字段为 `base_url/api_key/model/reasoning_effort`。真实地址、凭据和调用配置不发布。

```bash
PYTHONPATH=src .venv-train/bin/python scripts/run_harmonies_pilot.py \
  --root outputs/v2/UNIQUE_RUN \
  --pool outputs/v174/joint_pool_20261101/pool \
  --private-upstream /PRIVATE/UPSTREAM.json \
  --rules docs/v2/pilot/Harmonies_Known_Rules.md \
  --deadline ABSOLUTE_UNIX_SECONDS
```

同入口加 `--acceptance` 跑独立原生多动作验收。输出目录必须全新；不得删除失败账本来重置额度。

仅评估已有可信冻结提交时，追加 `--frozen-submission /RUN/experiment/checkpoints/SHA256 --deployment-profiles L20`。来源必须已冻结且哈希匹配，目的目录必须全新；记录为 `reused_frozen`，不冒充另一次开发。来源配置存在时必须沿用原总截止时间，原测试工作区和轨迹不会被复制给参与者。

```bash
PYTHONPATH=src .venv-train/bin/python scripts/report_harmonies_pilot.py \
  outputs/v2/UNIQUE_RUN/experiment
```

可信输出包含配置与环境/对手哈希、开发检查点、冻结提交、原生事件、逐局 GT 轨迹、模型预检/usage、资源账本和结果 JSONL/CSV。汇总保留失败、自然终局分数、随机接管比例，并按种子配对比较；10 局校准不能用于稳定排名。私人请求/错误材料和参与者产物不进入 Git。

跨配置试跑的成本审计：

```bash
PYTHONPATH=src .venv-train/bin/python scripts/audit_pilot_resources.py \
  outputs/v2/harmonies_pilot_20261115
```

审计读取父目录下各次试跑的可信账本，输出 `resource_audit.json`，保留失败配置与验收成本。已结算 usage 和未结算预留分列；预留不是确认账单，也不是严格的计费上界。缓存和推理 token 是输入、输出的子集。运行中的控制器尚未结算当前 CPU/墙钟，实时总数不完整；并行阶段的墙钟求和也不等于实验实际历时。CPU/RSS 超额、实际采样缺口和清理延迟单列。工程实现会话的模型使用、宿主机安装/测试 CPU 与可信服务 CPU 不在该账本内，不能把它称为整个项目的总成本。
