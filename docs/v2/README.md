# V2：规则变体与 Agent 开发能力评测

2026-11-15：V1 已收尾，V2 进入受控原生 Agent 开发试跑。
基线为 [`v1-final` 冻结说明](../V1_Closeout_zh.md)。新增 [Harmonies 原生 Codex pilot c3](pilot/README_zh.md)；校准试跑不代表正式排名。

## 目标

测试 agent 读取规则、修改代码、设计策略、训练和分析实验的能力，
同时记录 GT 交互、CPU/GPU、LLM token 和最终推理成本。
保留“LLM 每步直接走棋”作为独立对照，避免将其调用成本混同于本地训练成本。

## 复用与优先顺序

1. 复用 V1 的 16 个正式双人任务及联合对手池，原版 ID 和规则继续可追溯。
2. 按[固定设置与变体草案](../Game_Settings_and_Variants_zh.md)选择小批单因素变体，
   为规则差异建立独立标识；先验证规则、加速路径、合法动作和信息边界。
   文档建议的四游戏八变体仍是候选，不等于已实现或已确认平衡性。
3. 检查并接续现有受控 GT 服务、客户端和独立测试草稿；公开规则与接口，
   真实环境通过受控服务访问，正式测试集不用于调参。
4. 用原版策略迁移、规则感知参考策略、agent 开发策略形成对照。
   参考 bot 在变体下重新测量，保留未知，避免为凑档位自动扩大搜索矩阵。
5. 先做小型开发试跑，实测每轮 token、采样／训练吞吐及失败成本，再确定正式任务规模。

## 资源与版本边界

- [历史资源审计](../v175/Resource_Audit_zh.md)提供直接对局的逐游戏成本，不提供尚未实测的
  V2 开发训练时长保证。资源额度需在具体试跑任务中固定，不沿用已过期训练窗口。
- 每个变体固定规则版本、组件哈希、观察／动作 schema、结束和平局语义。
  修正原环境错误与新增自定义规则分别记录，不混为一个变体。
- 保留源码／配置／模型来源、开发和测试划分、失败轨迹及计量结果；发布更新继续提交并推送。
- 私有 API 配置和账单明细留在 Git 外；最终部署预算与开发资源分开。

本轮先执行原版 Harmonies Known 的开发与部署校准；变体实验尚未启动，V1 游戏规则、模型和历史结果未改写。
