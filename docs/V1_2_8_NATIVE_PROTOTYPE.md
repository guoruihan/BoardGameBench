# Harmonies 紧凑表示 / C++ 编码原型

2026-10-20。当前V128两卡PPO正常运行；本原型仅在本地a226单CPU核测试，不是已接入训练的新环境，也未改变运行中的源码。

## 结论

紧凑整数表示和C++有实测收益，值得继续。但主要价值是减少Python对象、逐元素循环和重复构造，不是原先物理内存装不下。不要把编码加速比当成整个训练加速比。

32个train环境（随机与habitat动作交替）、1,739个公开状态，包括终局。没有使用development/confirmation/test选择方案。每项计时五次取中位数：

|范围|Python基线|C++原型，含打包和调用|加速|
|---|---:|---:|---:|
|全部状态编码，逐个调用|0.3491秒|0.0758秒|4.61×|
|全部状态编码，每16个一批|0.3491秒|0.0559秒|6.25×|
|全部状态编码，每128个一批|0.3491秒|0.0531秒|6.57×|
|完整固定动作轨迹回放，逐步编码|0.5709秒|0.3469秒|1.65×|

最后一行同时包含reset、原Python游戏step、计分、合法动作和动作映射，只替换编码。它仍是CPU固定轨迹回放，不含模型推理、PPO更新、进程同步或共享GPU竞争。尚未声称真实PPO获得1.65倍加速。

所有特征与现有float32编码逐元素完全相等。额外测试覆盖所有32张动物卡及各放置计数、地形和动物ID、牌槽、终局、空批次、越界ID、布局拒绝和输出隔离；相邻PPO/collector测试合计39passed/2显式CUDA skips。游戏状态转移和随机源根本没有被C++原型改写。

证据：`outputs/v128/native_encoder_local_20261020_b/summary.json`和`profile.txt`，同目录保存C++/Python原型快照、编译命令、哈希及`.so`。前一轮仅编码测量保留在后缀`_a`目录；两次实测分别8.917/13.413 CPU核秒。追加回归/审查保守预留120 CPU核秒，记录在`_b/verification.json`；合计约0.03954 CPU核时，GPU费用为0。它们独立于已冻结训练的账本，不能覆盖或重复累加旧预检。

## 表示与信息边界

棋盘地形15种，理论上每格4bit，23格共92bit；动物ID（含空）需要6bit/格。仅棋盘二者理论约29字节，但这不是完整游戏状态：还需要牌、资源计数、回合字段和私有供给等。

原型将**生成网络特征所需的公开信息投影**存为161个int16，即322字节，生成的旧1346维float32特征仍为5384字节，模型输入完全不变。该投影不是可恢复完整游戏的序列化格式，不包含私有袋/牌堆，也不把隐含供给顺序暴露给网络。

不急于逐bit挤压到理论最小。先用uint8/int16连续数组通常更容易索引、检查和调试；地形集合、邻接、动物图案适合bitboard，而计数和ID不必都强行编码为位图。原型中128批预打包后调用/编码仅0.000672秒，含Python打包则0.0531秒，说明下一步应减少反复从字典构造数组，不只是继续优化C++算术。

## 下一步的实施顺序

1. 保持当前PPO继续运行；下一版独立训练采样器直接维护紧凑状态，或先接入原生编码验证全链路收益，避免每步`dict -> array -> dict`来回转换。
2. 训练内部可避开未使用的`reset_info()`规则说明深拷贝；对外标准环境接口仍返回原信息，不改变公共API契约。
3. 视profile扩展到批量`step + score + legal_mask + encode`，而不是每个小函数跨一次Python/C++边界。静态邻接、地形转移、卡牌图案常驻预计算；动作顺序和首个合法朝向必须一致。
4. 完整C++状态转移尚未实现。若实现，要保持原始供给/RNG、合法性、原始计分、自然终局、奖励望远镜和旧观测隔离；用参考环境逐步核对状态与掩码，再验证成熟PPO的行为概率和优化器恢复。
5. 等当前两卡任务完成后，独立测同128局、同checkpoint、同PPO参数的真实吞吐/CPU占用。收益成立才用新的源码/运行名续训，不热替换当前环境，不为提速放宽概率误差门槛。

当前还不知道紧凑C++全环境能让端到端PPO快多少；CPU/GPU同步和更新会限制收益。先完成一个可验证的原生批量路径，再考虑线程化或异步采样。

## 复跑

仅需现有Python环境、NumPy和g++，不自动安装软件，无GPU：

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONNOUSERSITE=1 \
  .venv-train/bin/python scripts/benchmark_harmonies_native.py \
  --out outputs/v128/native_encoder_local_<new_id> --games 32

.venv-train/bin/python -m pytest -q tests/test_v128_native.py
```

测试默认允许2–64个train环境，绑定一个CPU核，输出目录不可覆盖。C++使用`-O3 -std=c++17`，不使用fast-math。原型不作为pip包必需依赖，未安装编译器时常规原型测试显式skip。
