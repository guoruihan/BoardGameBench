# Harmonies V1.2.12：专家经验驱动的自主模型迭代

实现版本 0.4.17。目标是提高**不调用搜索的完整游戏模型策略**，不是拟合单个教师动作或把搜索包装成模型推理。

## 本次运行与边界

- 运行目录：`outputs/v132/autonomous_a226_20261020_a`。
- 硬窗口：2026-10-20 12:46:34–22:46:34，中国标准时间。实现、检查、失败重试、专家数据生成和最终评测均在窗口内；恢复不续期。
- a226：仅 GPU 0–3，四种方法各两个种子，独立单卡任务，每卡两个任务。每任务六个环境进程及一个 learner；控制进程与看门狗共享一个核，总共 57 个物理核，低于该机 64 核上限。
- b35：新专家数据任务使用 63 个工作核和一个控制核，共 64 个物理核。每局累计搜索上限 900 秒。只生成训练环境。
- 不停止无关任务，不修改游戏规则、计分、合法动作或信息权限。

## 如何使用数据

入口为 `boardbench.v132.data`。从无损轨迹库读取实际专家行为，要求训练集身份、完整自然终局、搜索预算至少 300 秒，以及逐动作回放验证。排除旧模仿内部验证环境和本轮预留环境；不把学生轨迹中的专家建议当成学生执行过的动作。

初始语料实际为 128 个环境、128 局、9,619 个公开状态，教师平均总分 116.0078125。这个均分只是教师训练语料统计，不能用于宣称新模型成绩。新生成的 128 局中预留 16 个环境，不进入本轮训练；预留仅约束本轮，不声称旧模型从未遇到过这些训练环境。

每轮课程训练从部分专家公开局面开始，未知牌序由原游戏引擎按公开条件重新采样。专家真实隐藏未来、终局私有快照、教师 rollout Q 值均不作为模型输入。接手后的真实奖励满足：

`sum(reward) × 150 = 学生终局分数 − 接手时已得分`

课程局的终局总分含有专家前缀，不能与普通开局成绩比较。日志单独保留 `normal_start_mean`、`reset_earned_score`。所有开发和确认评测均从普通开局开始，贪心纯模型行动到自然终局，不使用 STOP。

## 第一轮与自动后续

|方法|接手专家状态|信用分配|
|---|---|---|
|control|无|GAE λ=.95|
|random|50% 局随机接手|GAE λ=.95|
|backward|50% 局，从后段逐步移向前段|GAE λ=.95|
|mc_backward|同上|λ=1，完整剩余回报|

各方法两个配对初始化随机种子，从同一成熟 V130 模型、critic 和 Adam 状态出发；每轮目标增加 400 万个实际学生动作。正式模型为原 256 宽 FP64 网络，继续使用已验证的原生编码后端。

`pipeline.choose_plan()` 在每轮结束读取最新的同环境开发成绩：

- 课程方法稳定高于同轮对照时，延续它，并测试更小课程占比和轻量连续轨迹模仿。
- 课程没有转移到普通开局时，转测普通开局的长信用分配、连续片段模仿及较少课程依赖。
- 新专家语料完成后，进行完整回放验证并形成新不可变语料版本。
- 多轮缺少收益时，改变探索强度、信用分配和更新幅度；保留原模型，不覆盖失败前的模型。

连续片段模仿是小权重辅助损失：按轨迹采样连续最多 16 步的实际行为标签。它不是序列网络，也不保证学会规划；PPO 的优势和 value target 仍仅来自当前学生实际交互回报。

每轮 `decision.json` 是运行前的假设、父模型和语料；`decision_outcome.json` 是运行后的保留结果。旧模型、低效或互补方法都保留。自动规则是透明的预编码研究流程，不声称后台存在会任意改写新算法的 LLM。

## 评测、选择与最终交付

- 同一 32 个 development 环境用于曲线和 checkpoint 选择；64 个不同 development 环境用于逐局配对对照。开发集历史上使用过，不能当作独立最终泛化证据。
- 保存 latest 固定训练终点和 curve-best 两种结果，不混用两者。
- 到窗口末尾冻结一个候选，若时间允许，与原成熟模型在 128 个 confirmation 环境上做一次配对比较；本次迭代不读取其结果进行后续训练或重新选择。正式 test 不参与。
- `retained_best.json` 保存开发曲线候选和校验和；`model/best.npz` 为可直接推理的导出模型。
- `confirmation.json`、`REPORT.md`、逐轮 `results.json` 保存完整证据。候选在确认集未可靠获胜时，仍应保留原成熟模型，不把开发集峰值宣传为确定提升。

每个完整 PPO batch 保存模型、两个优化器、随机状态和计数器。额外记录每 batch 固定前四局学生轨迹：公开起点或环境 seed、实际动作编码、行为 log probability 和奖励；不是只存高分局。所有实际专家对局均保留原始轨迹，完成后加入压缩档案。未保存全部内部模拟树。
