# V1.7.2：现有 RL 与长预算搜索的开发集结果

完成前两部分：16 款游戏的完整公开输入／等价模拟接口，以及 456 局有效搜索对照。没有训练新版 RL。
在这四个环境、交换座位的小开发面板上，保留的搜索在 **13/16** 款胜率超过 50%，2 款持平，1 款落后。
这不代表所有搜索已经足够强。各方法都保留真实失败结果；不得把搜索失败解释成 RL 接近游戏最优。

所有决策均为单核 CPU；纯 RL 的时间是全局累计推理时间，不包含环境和模型加载，搜索同样排除实际环境执行与加载。
搜索计时至候选动作选定为止，后续诊断记录构造与轨迹写盘另计入整个任务墙钟。

## 对落后搜索的两次诊断

| 游戏 | portfolio 搜索胜率 | RL 续玩搜索胜率 | 保守改进搜索胜率 |
|---|---:|---:|---:|

| dominion | 0.0% | 0.0% | 62.5% |
| el_dorado | 0.0% | 0.0% | 50.0% |
| stone_age | 25.0% | 37.5% | 87.5% |

| 保守搜索 | 多候选决策 | 替换 RL 根动作 | 不足四轮 |
|---|---:|---:|---:|
| cascadia | 486 | 32 (6.6%) | 0 |
| dominion | 1123 | 22 (2.0%) | 62 |
| el_dorado | 1691 | 5 (0.3%) | 629 |
| stone_age | 1055 | 71 (6.7%) | 21 |

单纯换续玩策略没有普遍修复退化；加保守门槛后，这四款在同一开发面板上均改善，
其中 Stone Age 达到 7/8 胜，Dominion 5/8 胜，另两款各 4/8 胜。需要新环境确认这一改善。
实际 Dominion 轨迹曾出现：为了小幅模拟胜率差，
搜索跳过原 RL 本来会执行的有用出牌。有限样本、多次原子决策、候选最大值选择和近似 belief 都可能造成误差。
因此下一步不能只增加模拟次数，也不能把落后的搜索轨迹直接当优质教师。

El Dorado 的保守搜索绝大多数时间保留原 RL 动作，打平并不是强搜索能力的证据。

## 验证、成本和限制

- 有效结果 456/456 全部正常终局，实际累计决策时间均未超过对应上限。
- 共执行 514 个比较对局，包含被替换的 Dominion 和计时结果；实际对局 CPU 合计 **64.77 核时**，其中最终有效对局 57.24 核时。
- 所有已结束单核任务累计墙钟 **66.13 核时**，还计入模型加载、保存、选择、冒烟及性能检查；GPU 使用 **0**。开发编辑与本地测试不在此墙钟合计中。
- 每台机器占用不超过物理核心的一半；所有正式对局使用单核，不把多核算力隐藏在 900 秒里。
- 全量 family 回归 662 项通过，随后输入缓存、公开展示约束、报告和不确定性门槛分别通过定向检查；34 项 sampled-world 检查及真实 Dominion 展示牌回放通过。
- 最后输入／搜索定向检查 30 项通过；456 份轨迹哈希、57 组环境／座位配对及全部时间上限校验通过。所有远端任务已结束。
- 早期 Machi Koro／El Dorado 冒烟暴露无数值总分的处理错误，正式比较前已修正并复验；两次失败日志保留，未混入有效对局。
- 修正 Dominion 的公开 Moat 展示约束后重跑其 32 局；原始记录留存。
- 26 个仍适用的原始对局发生微小计时越界，最大为 900 秒档约 0.065 秒、180 秒档约 1.45 秒；加提前停算余量后重跑，只采用上限内结果。
- 输入是完整公开树；模型尚未训练。缓存／内部 transition 的局部提速不等于新 RL 整体训练吞吐。
- belief 匹配当前观察和已实现历史约束，不是精确后验；尚未利用全部可推知历史，存在确定化策略融合和后续策略偏差。
- 四环境开发集很小，方法选择使用同一开发面板，区间仅描述样本波动；正式 test 未用于调参。
