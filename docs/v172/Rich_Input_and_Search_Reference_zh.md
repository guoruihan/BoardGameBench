# V1.7.2：完整公开输入与终局搜索参考

本阶段完成输入／模拟接口和现有 RL 对长预算搜索的开发集比较，不训练新版 RL。
覆盖 16 个已合格的固定官方双人配置；Five Tribes 仍不进入正式 family。
游戏规则、合法动作、评分、隐藏信息边界和旧模型文件均不修改。

## 输入与模型

`families.rich_observation.PublicTreeEncoder` 对每款游戏的完整玩家观察、候选动作和
公开组件规则编码。保留棋盘位置、牌身份与效果、支付、方向、数量、阶段、双方可见进度及
公开历史；字符串使用固定词表或 UTF-8 字节，长整数保留精确文本，不做哈希或长度截断。
已有 24 维启发式特征继续供旧策略使用，不再作为新网络唯一的状态来源。

`families.rich_neural.ContextActorCritic` 使用按字段汇总的局面编码、独立动作编码和二者交互，
actor 同时读两者，critic 直接读局面；ragged batch 只包含真实合法候选。
静态词表、规则版本和布局随独立模型格式保存，拒绝把旧 checkpoint 当作兼容权重加载。
这是通过前向、梯度、重排、缓存等价和保存恢复检查的新输入模型接口，**尚未训练，不能宣称
已提升 RL 分数**。完整公开历史的计算成本仍需在下一阶段训练中控制。

## 每款游戏的搜索内容

统一框架执行多步真实规则模拟，各任务保留不同的规则／启发式知识：

| 游戏 | 输入补齐及搜索建议来源 |
|---|---|
| Harmonies | 双方完整盘面、动物图案／计分表；复用 habitat 动物布局、地形和保留 RL |
| Cascadia | 地块旋转／栖息地、动物支持关系、各类动物计分；布局与动物潜力候选 |
| Calico | 颜色／图案、边界、目标／猫组合；目标完成、按钮、猫组合候选 |
| Patchwork | 完整位图、拼布形状、时间轴／收入；空洞、区域完成和未来收入 |
| Century Spice Road | 资源、卡组、具体订单；交易链、补牌／休息与订单收益 |
| Jaipur | 货物、交换组合、令牌和整场印章；囤货、大单／抢售候选 |
| Splendor | 市场牌成本、折扣／贵族要求、保留牌；引擎、贵族进度与即时得分 |
| Gizmos | 完整引擎卡效果、触发链／能量；产能、激活与得分牌 |

| Targi | 边界棋子、交点、牌能力／展示排列；交点规划、组合和建牌收益 |
| Dominion | 手牌、公开买牌／弃牌记录、供应；引擎、瘦身、购买和终局牌组得分 |

| Toy Battle | 拓扑、栈层、部队能力和区域；总部／区域威胁和终局胜负 |

每次决策混合 RL 建议、领域启发式、长期因素强调版及不同动作类型候选，默认保留至多六个。
对同一候选组共享一次重采样未来，并交替采用领域启发式、长期因素版／habitat、保留 RL
作为自身后续策略；对手模型使用冻结 RL。每条分支只通过当时玩家能看到的观察选择动作。
真实终局胜负是主效用；有官方分数时加不超过 0.05 的归一化分差平局辅助。
Machi Koro 与 El Dorado 没有官方数值总分，保留 `None`，仅用真实胜负。
Toy Battle 同时报告勋章和官方胜负，勋章不等于唯一获胜条件。

这是一版有真实多步计算的独立参考，不是每款游戏都已完成专门的回合 beam／MCTS，
更不意味着最优策略。候选剪枝、后续策略和对手模型仍限制强度。

## 隐藏信息及预算

`public_world` 是可信模拟桥：保留确定性的规则执行记账，用玩家观察、公开组件表和历史约束
重建未知区域，未来随机源独立于真实对局 RNG。未知手牌／牌堆／移除组件不得直接用于评估。
检查固定搜索 seed 下修改真实隐藏排列不改变采样世界，同时检查根观察、合法动作和组件守恒。
Jaipur 已公开取得的货物、Calico 已公开拿取的板块、Dominion 可推知的区域牌下界等保留。

这是近似 belief，不是精确后验；不根据对手的历史策略给隐藏选择加权，也没有恢复观察契约
之外的全部过去私有记忆。确定化后续搜索存在策略融合误差。遇到未支持的约束会报错，不能
改为读取真实未来或把未到终局的叶节点伪装成实际回报。

预算为**每玩家每局累计决策时间** 30／180／900 秒，包含候选生成、模拟和 fallback 推理。
每次按剩余决策数分配时间；未完成整组候选的 round 不进入 Q。游戏没有改成逐步 900 秒。
记录实际累计／最大单步时间、模拟步数、完整 round、fallback、CPU 时间和完整率。

## 配对协议及恢复

1. 从旧冻结池保留 RL 和统一训练 `best.json` 取得候选，不直接晋升最新 checkpoint。
2. 独立选择 seed `172010000..172010007`，每个换座，选出本轮冻结 RL 对照。
   这只是小开发面板选择，不能声称找到了全局最强 checkpoint。
3. 新比较 seed `172020000..172020003`，每个 RL／搜索交换座位，环境第一玩家固定为座位 0。
   三个搜索预算共 16×4×2×3=384 局。未使用正式 test；四环境结论是初步诊断。
4. 保存真实执行的玩家观察、全部合法动作、动作、终局结果和候选 Q／样本数。
   不保存真实隐藏未来作为教师输入。结果和轨迹使用独立文件、哈希和原子写入。
5. `search_worker` 使用有限 CPU 队列，成功结果重启跳过；每个任务单核，远端总分配不超过
   每台物理核心的一半。源码快照、模型哈希、完整命令及私有资源配置保存在忽略的输出目录。
