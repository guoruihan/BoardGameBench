# Harmonies V137：从执行布局到自主选择目标

## 研究问题

V136在24个训练内专家局面×2个新未来上，指定目标两回合完成率从继续PPO的6.3%–8.3%提高到skills的60.4%–62.5%，但完整对局总分未可靠提高。目标选择器因开发均分0.075的差距未获准运行。V137保留这两个skills终点，明确区分目标选择、执行器更新、以及策略改变后的数据更新；不再按很小的开发分差淘汰能力分支。

研究成功标准是新环境上的真实整局总分，不是动物分、局部完成率或带选择偏差的模拟最大值。规则、信息边界、原始计分、自然终局不变。正式推理不调用搜索或在线LLM。

## 当前策略自己的状态与目标标签

两个父模型分别固定为V136 stage1 `skills_a/final.pt`与`skills_b/final.pt`，不是按确认集成绩选择。每个副本从相同训练seed范围独立完整玩64局，记录真正发生目标重选的时点，再按前中后期四个阶段、与成绩无关的固定哈希选取每局最多4个状态。

对于每个状态，枚举现有最多8个公开可行目标（含free-play），各模拟4个拟合未来和4个完全分开的复核未来。当前动作之后的全部决策使用当前worker和当前选择器，不偷用专家续玩能力。公共条件重采样不会读取原始隐藏随机序列；相同未来seed用于比较候选，但不同动作消耗顺序不保证抽到相同牌。

标签是实际自然终局总分。先用拟合样本选候选，再用新未来评估选择收益，按环境聚合区间。不能把样本内候选最高分称为最优上界。按环境留出约1/8状态，只用于目标选择器拟合诊断；这些仍是训练环境，不是独立策略确认集。复核未来和留出状态的Q都不进入训练损失。

执行加速复用原native编码和多进程环境；公开局面reset仅改内部采样入口，不改转移或合法动作。固定cohort复用进程，避免每批重启。逐批写入可恢复Q结果，保留生成轨迹、公开状态、父模型和数据SHA256。

## 试验设计

除两个固定skills父模型外，四种方法各2个训练副本，均从对应的同一skills终点出发：

| 分支 | Worker | 目标选择与训练 |
|---|---|---|
| control | 继续原PPO | 原启发式，检验单纯多训练的收益 |
| selector | 始终冻结 | 用当前worker的Q初始化，再做高层PPO |
| joint | 前1M环境动作冻结，之后更新 | 同样初始化，高层预热后两层PPO；弱目标BC权重0.005保留技能 |
| refresh | 与joint相同 | 第一阶段之后采集新局面、用当时的worker和选择器重新标注，再继续 |

Manager使用成熟worker的特征初始化，不继承旧版未训练的高层特征。初始化目标为原目标先验按`exp(Q/5)`重加权；critic拟合剩余真分`(terminal-start)/150`，而非把终局总分当剩余回报。高层PPO沿用实际持续时间的option累计奖励；gamma=1。冻结worker分支仍采样真实完整对局训练manager，计数为真实环境动作，不声称worker执行了参数更新。

每条第一阶段新增4M环境动作，第二阶段再4M；所有分支都继续，不做winner-only筛选。joint与refresh的第一阶段算法、随机种子完全相同，因此共用第一阶段检查点，到第二阶段才分叉，省去8M重复动作。第二阶段仅refresh重新标注：用新的训练seed范围64局、相同4+4独立未来；joint保留原标签的初始化后只继续PPO。各副本的初始目标数据在分支之间复用，避免重复生成。

## 评估、资源和恢复

新seed区间70M–80M：曲线512、开发审计512、最终确认512互不重叠，原train/test不变。固定终点统一确认，报告两个副本均值、逐环境配对区间和动物分；同时比较固定skills父模型、继续PPO和预先指定的上一轮强参考`V136 stage2 control_a`。训练内目标执行诊断单列，不能混成完整对局成绩。

运行机a226，GPU0–3；每卡最多2个独立试验，不做跨卡单实验。第一阶段6条训练使用3卡，第二阶段8条使用4卡；最多57个物理CPU（含controller），不超过该机一半64核；标签阶段两个单GPU子任务，每个7核；预检8核。GPU4–7和任何后来占用目标卡的无关任务均不抢占，启动前重新检查。

新guard为4小时，覆盖正式标注、训练、数据更新及确认；各训练阶段每试验最多4200秒，每个标注阶段最多1800秒。预检/本地验证另记成本，不沿用已过期V136预算。`label_cost.json`单独记录标注成本并并入最终完成记录；所有阶段保留原截止时间，恢复不会续期。

配置：`configs/v137_a226_goal_selection.json`。正式输出：`outputs/v137/selection_a226_20261022_b`。旧目录`selection_a226_20261022_a`只包含共享阶段优化前的预检；保留不覆盖，通过明确的预检目录链接把成本并入新运行，新源码仍必须重新通过预检。

在a226的命名tmux中运行：

```bash
bash tasks/main.harmonies-v137-goal-selection/run_a226.sh preflight
bash tasks/main.harmonies-v137-goal-selection/run_a226.sh launch
# 中断恢复，保留同一截止时间：
bash tasks/main.harmonies-v137-goal-selection/run_a226.sh resume
```

入口为`boardbench.v137.{data,training,campaign,preflight}`。启动门槛包括真实CUDA、公开局面模拟一致性、冻结worker不变、joint真实梯度、行为概率、验证数据不入损失、精确下一批恢复。`source/`封存源码；`labels*/{a,b}/progress.json`显示标注进度；`stage*/curves.svg`、`results.json`显示训练进度；`confirmation.json`和`completion.json`是完成依据。

这是有固定预算、明确分支和可恢复产物的自主实验，不是后台无限生成新算法或自动追加预算的LLM循环。
