# 无正常动作边界与模型复用

初次 2,176 局规则检查没有发现 Splendor/Gizmos 的无合法动作状态。随后对已写入的
859,192 条训练比赛记录进行审计，发现 19 条此类结果；旧 Splendor 开发联赛又发现
两条。这说明规则抽样不能代替长程边界审计。原始不完整结果均保留，没有补写终局奖励。

规则版本 2 的处理范围如下，详情和原始来源见对应游戏文档：

- [Splendor](games/splendor.md)：只有无法执行任何正常动作时才强制跳过，同时展示
  保留手牌。依据可追溯、明确署名的出版方裁定转引；并未宣称成功访问原论坛全文。
- [Gizmos](games/gizmos.md)：只有四类正常主动作全部无法执行时才强制跳过，正常结束
  回合，不制造 Pick 事件或抽取资源。依据授权数字版的原始修复提交，证据等级与作者
  FAQ 有区别。

双方永久阻塞都没有额外的终局裁定。强制跳过不能被偷换成判平；外部步数/时间上限
仍产生 `truncated`、无奖励的结果。已保存的合法构造用于回归这一边界。

## 权重复用与重新评测

两个修正保留已有 24 维候选特征的语义。新增强制动作仅在没有其他选择时出现，
因此可以复用旧权重作候选或新训练的初始化；这不说明旧规则成绩可直接搬到新规则。
Splendor 新增的信息揭示来自裁定，也不能以“保持兼容”为由省略。

迁移工具只支持这两款的 `1 -> 2`，不提供通用忽略规则身份的开关：

```bash
PYTHONPATH=src .venv-train/bin/python -m boardbench.families.migrate \
  --game gizmos --policy /path/to/old/best.json \
  --output /path/to/new/policy.json
```

输出必须是新路径。线性策略复制权重，神经策略复制模型并校验全部张量、prior 和
原文件哈希不变；输出独立 `.migration.json`，神经模型内部也记录源模型哈希及规则
身份转换。原始模型、成绩、优化器和轨迹不覆盖。加载器仍拒绝未经迁移的旧规则模型。

继续训练时使用新目录和 `--warm-start`，重新初始化优化器并产生规则 2 的新 rollout。
先在开发集重新比较原有候选及新候选，再冻结推荐策略，最后进行独立确认。旧开发集
只保留作旧规则诊断，不作为新规则下已经验证的能力证明。

此次修正仅改变两款游戏的运行行为。其他游戏已经冻结的选择和独立确认继续保留
各自源码身份；后续统一打包使用修正后的运行包，不把这些历史实验改标为新源码运行。
