# Harmonies 基础单人环境实施要求

本文规定 V1 的 Harmonies 任务：**23 格 A 面、120 枚基础地形、32 张基础动物牌、官方单人供给、不启用自然之灵**。交付同一规则引擎上的训练接口、搜索接口与人类交互网页。自主开发 agent 留在 V2。

环境 ID 固定为 `harmonies`，规则版本为 `harmonies_solo_a_v1`，与总规范一致。本轮注册工厂固定使用这一配置，不增加额外 variant 字段，也不增加 B 面、自然之灵或扩展牌的实现。

## 2. 棋盘、库存与初始化

### 2.1 23格拓扑

棋盘由五个竖列构成，列长从左到右为 **5、4、5、4、5**；短列向下偏移半格。不可直接复用 Take It Easy! 的19格棋盘。

采用与卡牌文件一致的 axial 坐标 `(q,r)`，六邻接偏移为：

```python
NEIGHBOR_DELTAS = (
    (1, 0), (1, -1), (0, -1),
    (-1, 0), (-1, 1), (0, 1),
)

# c 是从左到右的列，j 是每列从上到下的位置。
# cell_id 按这个列表的顺序取 0..22。
BOARD_CELLS = [
    (c, j - c // 2)
    for c in range(5)
    for j in range(5 if c % 2 == 0 else 4)
]
```

两个格坐标之差属于上述偏移，且都在 `BOARD_CELLS` 中时相邻。忽略越界邻居。初始化时提供 `cell_id -> (q,r)` 和邻接表，后续观测只需按固定 `cell_id` 顺序传输动态状态。

网页可以用平顶六边形绘制，中心坐标取 `x=1.5*q`、`y=sqrt(3)*(r+q/2)`；统一缩放和平移不影响规则。这恰好使短列向下偏半格。

### 2.3 `reset`

环境构造函数接收配置，保留 V0 契约：`reset(seed) -> (observation, info)`，`step(action) -> StepResult`。

每局开始：

1. 清空23格、动物标记、已持有及已完成卡牌。
2. 按上表建立资源袋，随机取出9枚，按固定槽位顺序分为三组，每组三枚。
3. 随机排列32张动物牌，公开前三张放到动物市场；其余保留为隐藏牌堆。
4. 初始化回合状态：尚未取资源组、没有待放资源、尚未取动物牌。

资源随机流、卡牌随机流、策略／搜索随机流彼此独立。基于同一个 episode seed 派生子种子即可。相同环境种子和相同动作序列须得到相同结果；策略搜索不得消耗真实环境随机流。

## 3. 棋盘堆叠：15种状态，包含空格

所有颜色都可以放到空格。下表从底到顶列出**全部14种非空合法堆叠及空格**；没有列出的堆叠均非法。数字 ID 可用于固定数值观测，但应固定并记录映射。

| `stack_id` | `stack_bottom_to_top` | 说明 |
|---|---|---|
| 0 | `[]` | 空格 |
| 1 | `[blue]` | 水 |
| 2 | `[yellow]` | 黄地形 |
| 3 | `[gray]` | 高1山 |
| 4 | `[gray, gray]` | 高2山 |
| 5 | `[gray, gray, gray]` | 高3山 |
| 6 | `[brown]` | 裸树干 |
| 7 | `[brown, brown]` | 高2裸树干 |
| 8 | `[green]` | 高1树 |
| 9 | `[brown, green]` | 高2树 |
| 10 | `[brown, brown, green]` | 高3树 |
| 11 | `[red]` | 单红地形，尚非建筑 |
| 12 | `[red, red]` | 建筑 |
| 13 | `[brown, red]` | 建筑 |
| 14 | `[gray, red]` | 建筑 |

放置一枚资源时，在目标格已有堆叠顶部追加该颜色，并检查结果在此表中。只能逐枚追加，不能抽出、换位、插到已有资源下面，不能移动已经放置的资源。

**格上已有动物 cube 时，一律不能再放资源。** 动物标记不改变原堆叠的颜色或高度。

特别注意：`[brown,brown,red]`、`[gray,gray,red]`、`[red,red,red]` 均非法；绿色不能继续叠高。裸棕和单红虽然本身不获得对应树／建筑分，但允许作为中间状态存在。

## 4. 回合与原子动作

每回合必须选取一次中央资源组，并放完其中三枚；可选取最多一张动物牌，动物放置次数不限。**取牌与放动物可在取资源前、三枚资源放置之间、放完资源之后发生。** 不采用强制“先拿卡、放三枚、自动放动物”的线性流程。

建议内部状态：

```text
board[23] = {stack_id, animal_card_instance_or_null}
token_market[3] = 三枚颜色的计数或列表
animal_market[3] = card_id 或空槽
active_cards = {instance_id, card_id, placed_count} 的列表
completed_cards = 已完成卡牌列表
turn_index
bundle_taken: bool
pending_tokens: 六色计数
card_taken: bool
public_token_history / public_card_history
private_bag_state / private_card_deck_state
terminal: bool
```

已完成牌保存到终局，不能从总得分记录中删掉。`instance_id` 表示本局卡牌实例；本版每种卡只有一张，仍采用实例标记便于恢复和回放。

| 动作 | 前置条件与效果 |
|---|---|
| `choose_bundle(bundle_id)` | 本回合尚未取组；将所选组的三枚转入 `pending_tokens`，该市场槽位清空，设 `bundle_taken=true` |
| `place_token(color, cell_id)` | 待放池存在该色；目标格无动物且追加后堆叠合法；消耗一枚，更新该格 |
| `take_card(market_slot)` | 本回合未取牌、槽位非空、未完成牌少于4张；取入该牌并置 `placed_count=0`，清空市场槽位，设 `card_taken=true` |
| `place_animal(instance_id, anchor_cell_id, orientation)` | 活跃卡仍有可放cube；当前棋盘符合第6节模板与目标条件；该卡进度加1，在锚点记录动物 |
| `end_turn(discard_card_slot=None)` | 必须 `bundle_taken=true` 且所有 `pending_tokens=0`；处理第7节结束与补给流程 |

卡牌放出最后一个cube后**立即**进入完成区，释放活跃卡槽。如本回合尚未取牌，可以随后利用释放的槽位取牌。不能放弃一张未完成牌来腾位置，也不能通过完成卡牌重置每回合一次的取牌限制。

**动物市场仅在回合结束时补齐。** `take_card` 后该槽位保持空缺；不能立刻揭示下一张，以免增加本回合信息。资源市场同样不在选组后立即补。

可选动物放置必须由动作明确选择，不自动执行。动物落点锁住该格，是否立即放动物本身是策略选择。`end_turn` 不要求先执行所有可能的动物放置。

非法动作应返回明确错误／按现有 V0 错误契约处理，并保持状态与随机状态不变；不能静默改成其他动作。

## 5. 终局计分与训练奖励

最终总分是所有地形分加所有已取得动物牌的分数。回合中可提供 `score_preview` 帮助 UI 展示，但它不是另加一遍的奖励；预览会因后续堆叠、连通变化而改变。

默认 RL 奖励：**非终止原子动作奖励0，正常终局动作奖励最终总分**。`info` 在终局附最终分数和分项明细。预算截断遵循 V0 Runner 的独立状态标记，不伪装成游戏自然终止。若参考方法增加奖励塑形，放在显式训练 wrapper 中，最终评测仍使用真实总分。

### 5.1 树

`[green]`、`[brown,green]`、`[brown,brown,green]` 分别得 **1、3、7** 分；逐格相加。裸棕堆叠得0分。

### 5.2 山

纯灰高度1／2／3分别得 **1、3、7** 分，但该格必须与至少另一个纯灰山格相邻；孤山无论高度均得0分。邻山高度不限。灰底红顶建筑不属于山，不能为相邻山提供连接。

### 5.3 田

对所有黄格按六邻接求连通分量。每个大小至少2的分量得 **5** 分，单格得0；大于2也只得5。两片原本得分的田被连成一片后，只剩一片的5分。

### 5.4 建筑

建筑是三个合法两层红顶堆叠之一。统计其邻格**堆叠顶层**的不同颜色数：至少3种得 **5** 分，否则0分。

红色可作为其中一种颜色；裸棕的棕色也可计入。空格、棋盘背景、动物cube不算颜色，建筑自身不算邻格。只看相邻格的顶色，不统计被盖住的底色。

### 5.5 A面河流

在蓝格诱导出的邻接图中，选两端，沿它们之间的最短路径计数，长度含两端；只计最佳河。实现为各蓝色连通分量的最大最短路距离加1，再取最大值；没有蓝格时长度0。

| 最佳长度 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7及以上 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| 河分 | 0 | 0 | 2 | 5 | 8 | 11 | 15 | `15 + 4 * (length - 6)` |

这采用规则p.8“最短路线、最好的一条河”的图算法解释。不能用蓝格总数、最大连通块大小、或最长简单路径替代。多个不连通河流不累加；环和分叉需要按最短路实际计算。

### 5.6 动物牌

对每张已取得的牌取 `score_by_placed_count[placed_count]`，然后逐牌相加。数组已经是累计档位，不能将前面各档累加。未放动物的牌得0分；未全部完成没有额外罚分。

## 6. 动物牌数据与图案匹配

读取 `data/harmonies/animal_cards.base32.v1.json` 顶层 `cards` 数组；应恰有32个不同 `card_id`。字段约定：

| 字段 | 用途 |
|---|---|
| `card_id` | 稳定牌ID |
| `name_en` | 展示名称，不参与规则判断 |
| `pattern_cells[].cell` | 相对锚点的 axial 坐标 `[q,r]` |
| `pattern_cells[].terrain`、`height` | 格子要求的地形与精确高度 |
| `stack_bottom_to_top` | 普通地形精确堆叠要求 |
| `top_color`、`allowed_base_colors` | 建筑模板：两层红顶，底色允许红／棕／灰 |
| `anchor_cell` | 模板的动物落点；本文件已规范为 `[0,0]` |
| `cube_count` | 该卡允许放出的动物数量 |
| `score_by_placed_count` | 长度 `cube_count+1`，从0次到全部完成的累计分 |

将模板绕锚点旋转0–5次，再平移到棋盘上的目标锚点。一次60度旋转可取 `(q,r) -> (-r,q+r)`。**只旋转，不镜像**。所有模板格必须在棋盘内并匹配对应堆叠；模板之外的格不受限制。

匹配需要区分以下情况：

- 树和山的高度必须精确相等。高2树不能替代高1树；高3山不能替代高2山。
- 建筑必须高2且红顶，底色可为红／棕／灰；**无需满足建筑本身得5分的三种邻色条件**，也可参与动物模板。
- 只有动物实际落点必须没有cube。模板的其他格可以已有动物，仍可参与匹配。
- 多次栖地可共享格子，包括同一张牌的不同次完成；每格仍最多一个cube。
- 动物放置后不再持续要求原栖地保留。之后合法地改变其他模板格，不撤销已放动物或卡牌进度；动物所在格本身仍不能再叠资源。

`orientation` 是匹配验证所用的模板方向，不是动物的新状态。如果同一张牌、同一锚点存在多个合法方向，它们放置后的真实状态相同，可在合法动作列表中只保留一个合法见证方向。不能因为几何去重丢掉其他不同锚点。

引擎不要重新解释上游资料的链式 `position` 字段：本包 `cell` 已经展开为相对坐标。卡牌读取与32牌数据校验应在启动时完成，搜索内复用编译后的模板。

## 7. 结束回合、单人弃置与末袋裁定

`end_turn` 接收可选的动物市场弃牌槽位。仅当本回合**没有取动物牌**时，才可选择一个非空市场槽丢弃并准备补牌；也可以不换。参数合法性先检查，非法时不得产生任何状态改变。

按下列顺序实现回合边界：

1. 确认取过资源组且三枚已全部放完。
2. 回合末检查空格数：若空格≤2，游戏正常终止，按当前棋盘与牌进度计分，不进入下一回合。
3. 若没有触发棋盘终止，将市场另外两组共6枚资源永久移入公开弃置计数。**这些资源不回袋。**
4. 检查袋中剩余数量：若少于9，按本项目裁定立即终止，不建立部分供给，不开始第14个仅一组资源的回合。剩余袋中资源不放到棋盘上。
5. 若可继续，按槽位顺序补三组、每组三枚；执行已请求的可选动物弃牌，并将动物市场空槽按槽位顺序补到三张。
6. 回合号加一，清空待放池，重置 `bundle_taken` 和 `card_taken`。更新玩家可见观测。

第2或第4步已终止时，终局不再抽牌或揭示下一轮供给；终局边界上的换牌请求不改变得分，也不必执行新的牌堆抽取。事件日志标注终止原因 `board_full_enough` 或 `supply_exhausted`。

**末袋规则是本项目明确的实施裁定。** 官方原文描述袋空无法补给的终止条件，没有单列单人剩3枚的补牌方式。本版固定“无法完整补足下一轮9枚即结束”，所有训练、搜索、网页、同种子比较均一致执行；不需要为此提供多套行为开关。

120枚不能保证棋盘先结束：标准单人每回合使用3枚、丢弃6枚，且资源可堆叠。附带 witness 给出13回合后39枚只占13格、仍有10空格且袋余3枚的合法例子。因此需要覆盖供给耗尽，而不是只检测棋盘。

本裁定下，自然游戏最多13个完整回合，可更早因棋盘结束。每回合最多使一张牌从牌堆进入市场（取牌或换牌二选一），32牌足够，不引入弃牌堆重新洗入机制。

## 8. 观测、搜索与网页

观测包括固定拓扑、23格stack及动物关联、公开资源与动物市场、活跃及完成卡牌进度、回合标记、待放资源、可行动作。当前牌面模板和分数可由公开 `card_id` 查本包卡库。已公开／弃置的资源与卡牌历史可作为公开信息提供。

不要在 observation 或策略 context 中提供隐藏牌序、真实未来资源序列、真实环境 RNG 或可用于复原该序列的 episode seed。参考搜索获得的状态副本必须保留公开局面，并独立抽样与公开历史一致的未来；不能直接带走真实引擎剩余洗牌序列。

RL wrapper 应使用固定形状数值编码和动作mask，保持本节游戏语义；可把动物市场／活跃卡槽填充为固定大小，空槽使用明确的数值编码与mask。支持原子动作即可，不要求一次输出整回合组合动作。真实回合数 `turn_index` 与原子决策次数 `decision_index` 分开记录。

网页至少支持手动游玩、请求策略建议、从当前局面接管、单步／自动策略播放和回放。展示23格堆叠高度、三组供给、待放资源、三张市场牌、活跃牌进度、已完成牌和分项分数。合法动物位置用提示展示，执行由玩家选择；结束回合按钮仅当 `bundle_taken=true` 且 `sum(pending_tokens)==0` 时启用。

不必做三维引擎：二维六角格、顶色、高度标记与点击查看完整stack足够。网页操作与RL动作均调用同一规则引擎；可视化层不能独立实现计分。

同题挑战固定资源流与卡牌流。不同取牌／换牌动作可能改变牌公开的时机，因此不承诺每回合动物市场完全一致；不得为了视觉上的一致性更改供给规则。

## 9. 必须通过的11项验收

1. **拓扑正确**：23个唯一坐标，列长5/4/5/4/5，邻接对称、最大度数6，边缘与图案越界按固定坐标处理。
2. **库存守恒**：初始六色总数正确；市场、待放池、棋盘、弃置、袋中逐色合计始终等于初始库存；单人弃置绝不回袋。
3. **堆叠完整**：15状态与逐枚合法转移全部覆盖；错误底座、超高、绿色封顶、动物占格均拒绝，非法动作不改状态或RNG。
4. **回合自由顺序**：取资源前及三枚之间可取牌／放动物；每回合至多取一次牌；完成牌立即释放槽位；不能通过空待放池跳过必做资源动作。
5. **延迟揭牌**：取牌后市场空槽保持到回合末；未取牌可换一张，取过牌不能再换；补牌顺序固定。
6. **32牌数据**：32个唯一ID，分值轨道长度匹配cube数；为每张牌构造至少一个匹配局面及错误高度／边界反例；有锚点时必须检验目标占用规则。
7. **栖地语义**：六方向可匹配；非锚点动物不阻断模板；合法栖地可重叠；建筑不需本身得分即可匹配；之后改变其他格不撤销动物；不允许镜像作为额外变换。
8. **地形计分**：覆盖树1/3/7、孤立山0、山1/3/7、田合并、建筑邻色去重、蓝河0–7及以上、环与分叉、多个河只计最好；与人工小局面分项结果一致。
9. **结束与奖励**：空格≤2仅在回合结束检查；全部资源放完仍允许可选动物动作；正常终局只发一次最终奖励，牌档位不重复累加，终局后不可继续动作。
10. **末袋见证**：使用 `reference/bag_exhaustion_witness.json` 复现未填满棋盘而供给先结束；袋余3时不补部分市场、不提供额外一轮，并保留正确终止原因。
11. **一致与恢复**：同seed同动作得到同轨迹；snapshot恢复含回合中待放资源；真实引擎、RL wrapper、人类网页执行相同动作产生相同局面；搜索采样不改变真实下一次供给。
