# Micro Tiles 与 Take It Easy! 实施规范

## A. Micro Tiles

### A1. 冻结规则

本任务是自定义控制环境。采用3×3方格、四邻接、3种等价颜色。空格编号 `cell_id=3*row+col`，row/col均为0–2。

每次供给两枚独立均匀、有放回抽取的颜色；可相同。选择一枚放入任意空格，另一枚弃掉。不允许旋转、堆叠、移动或跳过。第九次放置后结束，不再抽第十对。

总分是：每条两端同色的无向相邻边+1；每条填满且同色的行／列+3。无对角线奖励。棋盘有12条无向边、6条可得奖励的行列。两项分数叠加。

### A2. 数据与动作

```text
board: int[9]             # 空格=-1，颜色=0,1,2
offers: int[2]            # 未结束时有两枚；终局可以返回空数组
placed_count: int         # 0..9
action: {offer_index: int, cell_id: int}
```

建议 RL 动作ID为 `offer_index*9+cell_id`，18维mask只允许空格落子。即使两枚同色，也可保持两个合法ID；搜索可合并等价后继。

同种子预生成九对供应或采用等价独立RNG，实际未来不进入公开观测。正式 reward 按总规范，仅终局发分。

### A3. 验证样例

`data/scoring_examples.json` 包含以下三个填满棋盘：

- 全部同色：12条同色边+6条同色线，得30分。
- 每行一种颜色、三行各不相同：6条同色边+3条同色行，得15分。
- 三色循环方阵：没有同色邻边或同色整线，得0分。

另需覆盖：重复供给、已占用落点拒绝、非法候选编号、终局不再抽取、同种子动作序列复现。小规模末局状态可用精确枚举核对搜索；不要提前宣称全起始状态已经求得最优。

### A4. 轻量方法与网页

启发式可比较当前得分变化与尚可完成的行列；搜索从真实分布独立采样未来；RL 采用固定18动作mask。这里不把启发式公式写进引擎。

网页显示两枚供给、9格棋盘、当前两项得分，以及候选落点。完成一局不需要输入JSON。该任务主要检验全链路，不承担最困难策略任务的定位。

## B. Take It Easy! 标准单人

### B1. 规则与范围

19格六边形棋盘，27种不同的牌，无放回随机揭示。每步必须将当前牌放进任意空格；不要求邻接已放牌。不允许旋转、挪动或跳过。放满19张结束，未用8张不参与本局。[T1]

三方向数值分别为：竖直 `{1,5,9}`，左下至右上 `{2,6,7}`，左上至右下 `{3,4,8}`。27种牌是三个集合的笛卡尔积。牌的朝向固定；一条贯穿棋盘的完整直线上，对应方向的数值全部相同，才得到“数值×格数”，否则0。总分为15条线之和。[T1]

不实现太阳／月亮加分、额外邻接限制或规则书的其他变体。

### B2. 固定坐标约定

棋盘是以下轴坐标，按 `(q,r)` 字典序排序赋予0–18的cell_id：

```python
cells = [(q, r) for q in range(-2, 3)
                for r in range(-2, 3)
                if max(abs(q), abs(r), abs(q+r)) <= 2]
```

相邻偏移为 `(1,0),(0,1),(-1,1),(-1,0),(0,-1),(1,-1)`。

若渲染使用 `x=1.5*q`、`y=sqrt(3)*(r+q/2)`，y向下，则固定：

| 直线集合 | 视觉方向 | 比较牌字段 |
|---|---|---|
| `q=c` | 竖直 | `vertical` |
| `q+r=c` | 左下至右上 | `rising` |
| `r=c` | 左上至右下 | `falling` |

每组 c=-2..2，共15条线，三个方向的线长都为3、4、5、4、3。渲染与计分共用这份映射，不再各自判断方向。

### B3. 固定牌编码与观测

对 `V=[1,5,9]`、`R=[2,6,7]`、`F=[3,4,8]`，定义 `tile_id=9*i+3*j+k`，牌值为 `(V[i],R[j],F[k])`。

```text
board: int[19]                 # 空格=-1，否则tile_id
current_tile: int|null         # 终局为null
remaining_tiles: bool[27]      # 尚未揭示；不包括当前牌或已放牌
placed_count: int              # 0..19
action: {cell_id: int}         # 0..18
```

剩余牌集合可以由全部公开历史推导，直接提供不增加信息权限。终局的null在数值适配器中编码为明确哨兵和mask，不进入神经网络浮点数组。

每步放置后由引擎自动揭示下一张，不暴露单独“抽牌”动作；第19次放置后直接终止。

### B4. 供给、搜索与比较

可按seed生成27张牌的均匀随机排列，本局只用前19张。同供给挑战让各策略得到相同排列。

搜索根据公开的剩余牌集合重新无放回采样，其随机源与真实排列分离。真实存档可保存排列用于恢复，但普通搜索不能拿真实未来做规划。先知规划器如将来加入，只能单独标注，不参加正常baseline排名。

### B5. 独立计分样例

`data/scoring_examples.json` 给出一个使用19张不同牌的完整布局。同一q列固定vertical，其余数值按文件逐格列出。它有：

- 五条vertical线贡献 `3*1+4*5+5*9+4*1+3*5=87`；
- rising方向仅 `q+r=-2` 的三格线全部为2，贡献6分；
- 其余rising线与全部falling线无效。

因此预期总分93。该样例不是规则书中的178分例图，不得混称。文件内列出每格坐标、tile_id和三方向数值，可验证方向映射与完整布局计分。

还必须覆盖：27牌唯一、每格恰属3条计分线、无放回、单格数值破坏整线、非法动作不消耗下一张牌，以及加入搜索后真实牌序保持一致。

### B6. 方法与网页

最初比较随机、成线机会启发式、预算受控的采样搜索、一个真实训练的RL方法。若加入value辅助搜索，总方法数不超过5。

网页展示当前牌、合法落点、已完成／仍有机会／已破坏的线及真实得分说明。支持逐步播放策略、提示、接管、同供给比较。人类尚未完成时不展示bot后面的供给和完整终局布局。
