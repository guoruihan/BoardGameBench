# V1 范围与共同架构

## 1. 成功标准

V1 的目标是建立可验证、可训练、可被人类体验的策略任务。交付三个环境及人工参考方法，为 V2 的自主学习系统评测提供可靠任务基础。

每个任务需要：

1. 唯一规则实现、确定的规则版本、可复现供给与计分。
2. 本地 RL／搜索接口、公开观测与合法动作。
3. 人类完整玩一局的网页，以及策略演示、提示和接管。
4. 至少一项真实参数训练的 baseline，加启发式与搜索对照。
5. 可恢复的策略产物、真实评测结果和必要开发证据。

本轮不评测参赛 agent 的自主模块开发；不加入多智能体学习、opponent shaping、视觉识别任务、隐藏规则发现、远程 API 协作或生产环境部署。

## 2. 固定配置

| task_id | rules_version | 范围 |
|---|---|---|
| `micro_tiles` | `micro_tiles_v1` | 3×3三色，两枚独立均匀候选，相邻+1／同色行列+3 |
| `take_it_easy` | `take_it_easy_standard_v1` | 单人标准规则，19格，27种牌，无旋转 |
| `harmonies` | `harmonies_solo_a_v1` | 单人三组供应，A面，32动物，禁用自然之灵，末袋不足9结束 |

这是可实施的第一版配置，不再把 Micro 分数权重或卡牌数据作为阻塞项。改变这些行为须产生新规则版本，不能让不同方法在未记录的不同配置上比较。

## 3. 模块职责

| 部分 | 职责 |
|---|---|
| 游戏引擎 | 状态转移、合法动作、抽取、计分、终止、局面保存 |
| 任务适配器 | 数值特征、动作编码／mask、规划分支、UI视图 |
| Solver／baseline | 选择动作、管理模型、搜索与策略保存 |
| 训练程序 | 采样、参数更新、验证集挑选、保存训练记录 |
| V0 runner | 多局执行、资源和日志、已有 checkpoint 与评测框架 |
| 网页轻后端 | 游戏会话、玩家动作、请求策略、回放 |
| 网页前端 | 绘制状态、合法动作交互、回放和结果比较 |

引擎是网页和训练的共同依赖。前端可以生成候选输入，但有效性与计分以引擎为准。前端显示的“潜在得分”必须和真实已得分区分。

## 4. 与 V0 的接口关系

保留实有契约：

```python
observation, info = env.reset(seed)
result = env.step(action)
# result: StepResult(observation, reward, terminated, truncated=False, info={...})
```

配置由构造函数或现有 task factory 传入，不改变 reset 的参数签名。新环境可提供以下辅助能力，由适配器调用：

```text
task_spec()            静态拓扑、规则版本、动作描述
observe()              当前公开观测，无副作用
legal_actions()        合法候选或mask，无策略筛选
score_breakdown()      当前计分预览与终局计分明细
save_state/load_state  完整局面复现
```

名字可按现有项目惯例调整，但以上语义要具备。不要为这些小接口增加新服务或庞大的插件体系。三个 task 的工厂注册和显式适配器就足够。

## 5. 观测与动作

动态观测采用 JSON 兼容数组／对象，静态拓扑只需初始化时提供。数组顺序与 `cell_id` 固定，邻接表描述关系，无需每步重复自然语言。

V1 规则和完整牌型定义是公开的。玩家只看不到未来实际抽取顺序。根据已经公开的信息能确定的剩余资源计数可以直接提供，避免测试无意义的记账能力。

RL 编码需要有限数值、明确 dtype／shape 和动作 mask。JSON 观测可以有语义上的空值，但送入数值模型前必须编码为约定的值与mask。终局必须能正常编码，全零动作 mask 不得触发一次额外采样。

Harmonies 使用有类型的原子动作。给定状态的全部合法动作可以枚举为候选列表并计算候选特征，策略在候选中选择；也可用层级动作头。候选列表只排除违法动作，不允许由运行时先挑出“最优若干动作”。

## 6. 随机性、搜索和存档

真实游戏、训练、搜索分开派生种子。不同次数的 hint 或 rollout 不得改变真实下一张牌。

`save_state` 用于人类存档和恢复，应能复现真实后续，包括回合内标志和随机状态；策略 checkpoint 用于跨新局复用模型。这两种产物不能混用。

规划分支从当前可见信息重建局面，并对未揭示资源重新独立采样，保持对应的有放回／无放回分布。不能通过复制完整真实供给排列向普通搜索泄露未来。无需在 V1 建立对恶意程序的安全隔离，按可信实验代码契约实现即可。

## 7. 回报、终止与资源

三个环境默认：非终局奖励0，终局奖励为完整真实得分；终局 `info` 按 V0 runner 约定提供 `score`。计分预览不是额外发放的奖励。奖励塑形放在训练包装层，并统一用真实终局分数评价。

非法动作抛出 V0 `InvalidAction`，环境状态和 RNG 不变。runner 可按原逻辑计入动作请求。终局后的动作应明确拒绝。预算截断不伪装成自然终局。

记录 `episode_id`、`turn_index`、`decision_index`。Micro／Take It Easy! 一次放置对应一次决策；Harmonies 一回合内可能有多次决策。训练参数须说明折扣作用在原子动作还是回合上；短局终局得分任务可优先试 `gamma=1`，避免隐含偏好较短的动作序列。

各任务配置必须覆盖 V0 的16次动作默认值；不能靠错误截断让策略看起来更快。Harmonies 可给明确足够宽裕的动作上限，并依自然规则终止；另记录真实步数。

## 8. 开发阶段

按 Micro → Take It Easy! → Harmonies 顺序做完整闭环。共用框架只提取确实重复的部分。每次进入下一任务时保留之前任务和 V0 的回归验证。

先验证引擎，再判断 baseline 的强弱。V1 可提供原生批量采样或并行进程作为后续优化，但第一轮不要求 GPU 游戏引擎、多机训练、热更新服务或异步任务队列。

新游戏的规则样例必须独立给定预期结果，不只检查实现自己的输出能否读回。本包样例有助于起步，但不能替代每个模块的规则验证。
