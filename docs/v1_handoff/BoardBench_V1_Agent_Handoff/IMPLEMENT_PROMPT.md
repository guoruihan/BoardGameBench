# 交给本地 coding agent 的指令

请在现有 BoardBench V0 仓库基础上完成本包的 V1。先读 README 和 docs，再检查当前代码与实际运行方式，随后直接推进实现，不停留在方案说明。

## 工作目标

实现 Micro Tiles、Take It Easy!、Harmonies A面官方单人三个任务；每个任务具有同源规则引擎、数值化 RL 输入和合法动作处理、预算受控的搜索、本地人类可玩的网页，以及人工设计方法得到的可加载策略产物。V2 自主开发 agent 不在本轮范围。

完整卡牌定义已经在 `data/harmonies/animal_cards.base32.v1.json`，不需要用户重新找卡图。按包内规则实施；不要将旧调研稿的“尚未取得卡牌数据”等历史状态当成待办。

## 执行顺序

1. **检查基线。** 阅读已有仓库指令，记录 Git 状态；运行现有适量测试。按 `02_V0_INTEGRATION.md` 核实现存问题，只修仍存在的问题。保持 V0 risk 示例可用。
2. **Micro 完整闭环。** 完成环境、计分、RL／搜索适配、最小网页；先用随机与启发式，再跑真实参数更新和小规模评测。建立后两个任务复用的页面和策略加载方式。
3. **Take It Easy! 完整闭环。** 引擎、三方向计分、同牌序挑战、搜索与一个 RL 方法；保存验证集选出的策略，报告实际性能和延迟。
4. **Harmonies 完整闭环。** 先做地形／堆叠／动物匹配／回合顺序和计分样例，接入全部32张牌，再做网页和策略。只接受合法原子动作；不能替玩家自动完成动物放置。
5. **整理验收与实验。** 每任务比较3–5类方法，输出训练投入、真实得分分布、在线耗时和实际可加载权重。按验证结果设置网页策略标签。
6. **交付审阅包。** 输出代码、运行说明、配置、测试证据、网页截图或操作记录、训练结果与策略权重清单、简洁 `IMPLEMENTATION_STATUS.md`。列明已完成、待跑大规模实验、已知限制；不要把 smoke run 说成强策略。

每完成一个任务先使其独立可玩、可训练、可评测，再继续下一个。对同一任务可先完成规则和网页，再进行较长训练。

## 实现边界

- 继续使用 V0 `reset(seed) -> (observation, info)`、`step(action) -> StepResult` 和 Solver 生命周期；游戏专属接口可以扩展在具体环境或薄适配层。
- 训练走本地 Python 引擎；网页用同一引擎的轻后端。可以复用当前静态页面方案，也可以使用有清晰收益的小型前端构建；不要求纯浏览器运行训练模型。
- 新依赖按用途设置 optional extras，锁定实际验证过的版本；不为新增一个任务引入分布式服务、权限系统或任务编排平台。
- 非法动作不得改变局面或真实 RNG；搜索随机数与真实供给分离。不要通过读取真实未来牌序提升 baseline。
- 所有训练和评测都记录规则版本；Harmonies 不要混入双人五组供给。末袋不足九枚的处理采用包内明确的实施裁定。
- 候选算法由实现者选择，最初以随机、启发式、采样搜索、一个 RL 方法组成四类即可。不要把同一算法不同 checkpoint 计作很多种方法。
- 不要求先实现“所有任务通用的一套神经网络”。任务适配器和策略网络可以不同，共享评测方式即可。
- 需要调用本地训练程序与小模型；本轮无需调用远程 LLM，也无需重做 V0 预算网关。

## 训练和诚实报告

先跑短训练确认动作合法、数值稳定和权重真实更新，再按配置逐级增加预算。不要直接启动无人知晓的无限训练。记录 CPU／GPU、墙钟时间、环境步数、优化步数、超参数、随机种子和 checkpoint。

用训练种子拟合、验证种子选模型和难度、测试种子最终报告。真正的策略提升需要同一评测协议下的证据；没有提升则报告结果与诊断，不能伪造曲线、标签、权重或 SOTA 声称。

用户已有可用计算资源不代表当前机器一定有 GPU。先探测本地设备；CPU 要能运行引擎、网页和 smoke 验证。设备或预算不足时交付可复现训练命令和已完成结果，并精确注明长训练尚未完成，不把它写成全部验收通过。

## 实现日志

保持简洁的三个记录：

- `docs/IMPLEMENTATION_STATUS.md`：当前完成程度、运行方式、关键限制。
- `docs/DECISIONS.md`：实际影响规则、接口或结果的决定。
- 实验目录中的 `config.json`、`metrics.json`、checkpoint manifest：记录训练与评测事实。

具体目录可适配现有项目；不要求为了文件命名搬动所有旧文件。常规实现选择自行判断，只对缺失访问权限、明显超出范围或不可恢复的操作请求用户决定。
