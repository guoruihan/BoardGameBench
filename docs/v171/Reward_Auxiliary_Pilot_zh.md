# V1.7.1：终局分解辅助学习对照

本轮落实[奖励信号检索](../v170/reward-signals/README.md)中的三个实验方向。
这是统一候选 PPO 的受控试跑，不承诺收敛或追平旧的专用 Harmonies 模型。

## 实验矩阵与初始化

16 个已合格任务均从上一轮 B 组的最终通用模型继续。选择“最终”由本协议固定，
没有根据最终测试成绩选模型；保留原模型、优化器、轨迹和对照结果。
新实验重新初始化 Adam，并为同一游戏的所有条件添加相同的辅助头；原 actor/critic
权重逐项复制。零辅助系数不改变原 PPO 的共享参数更新，已用回归测试核对。

| 条件 | PPO 终局奖励 | 辅助损失系数 |
|---|---|---:|
| win | 胜 +1、和 0、负 -1 | 0 |
| aux | 同上 | 0.25 |
| mixed | 0.75 × 胜负 + 0.25 × tanh(终局分差 / 训练分差标准差) | 0.25 |

14 个存在原生数值结算分数的任务各跑三组。Machi Koro 和 El Dorado 没有胜利点总分，
仅跑 win/aux，共 **46 路**；它们的地标、金币、到达终点棋子、路障数量仅作为结果辅助标签。
Toy Battle 的勋章和 Jaipur 的轮胜数也不等同于普通累计分数；mixed 是明确改变偏好的实验，
仍以真实比赛胜负评测，可能损害胜率。

三组使用同一个固定对手面板，均匀抽样共同初始模型、既有保留策略和启发式；神经对手
训练时随机采样。对手抽样只依赖 run seed、批次和局号，不受 minibatch 随机数或游戏长度影响。
本轮不动态更换训练对手，用于隔离奖励/辅助监督的作用；验证后的候选仍归档保留。
所有游戏遵循同一规则，Harmonies 的旧专用模型也只是既有面板成员。

## 标签与信息边界

- 仅自然结束的完整比赛生成终局标签；截断、未决规则、运行错误不伪造零分或输局。
- 预测自身/对方终局分数、分差，以及已有 `score_breakdown` 的数值分项。
  字典保留稳定字段；变长数值列表求和，避免将第几个历史条目误当作固定语义槽。
- 每游戏从旧 B 训练轨迹的前 32 个完整比赛估计均值和标准差，双方视角一起校准，
  标准差下限 1；归一化标签截断到 ±10。固定校准文件及输入轨迹 SHA，不读取验证或测试结果。
- 不适用或缺失字段用布尔 mask 排除出损失，不能以零伪造标签。
- 新 head 连接原公开候选编码器的 pooled 表示。终局标签只进入损失，不能进入 actor 输入、
  动作排序或游戏规则；没有引入隐藏手牌、未来抽牌或新的观察字段。
- aux 保留胜负 value/GAE；mixed 的同一个 critic 和 GAE 一致使用混合奖励。
  这些都是终局监督，没有声称获得逐步密集奖励。

现有 24 维候选特征和固定先验 KL 保持不变，因而表示能力或先验约束仍可能是瓶颈。
记录 actor 残差、相对先验的动作差异、prior KL、value MSE 与逐头辅助误差，以便区分
“辅助任务拟合成功”和“策略真正改进”。训练批内误差不是独立预测泛化成绩。

## 预算、评测与停止

- 每路最多 1 小时，覆盖初始化检查、采样、更新、写盘与开发验证；本批最多 46 条件小时。
  GPU 由多个任务共享，不能把条件小时误写成独占 GPU 小时。
- 每路 4 个 CPU actor + 1 个 learner，按不同物理核绑定；每机总分配含控制进程不超过半机，
  a 系列另有 128 核上限。只在重新检查过的空闲 GPU 上启动，不停止其他任务。
- 保持 PPO LR 1e-4、4 epochs、batch 128、gamma=1、lambda=0.95、entropy/prior-KL=0.01。
  每批 24 局，learner 视角按局号交替先后手。
- 根据旧 B 实际训练量设置同游戏共同决策上限：`max(100000, min(500000, floor(0.4*N/10000)*10000))`。
  完整批次可能超过上限一个批次；逐路记录实际 learner/env 决策量，不宣称严格相等的交互数。
- 16 个开发 seed × 双方换位 × 固定对手面板；训练、开发和确认仍使用独立 seed 分区。
  中间/终局检查统一报告胜率、真实得分与分项、完成情况和消耗。运行不足不冒充完整比较。
- 有充分时间及正向区间时，沿用 128 开发 seed 的候选/原策略配对确认；不访问正式测试集，
  不自动发布替换生产 bot。单次训练重复和较小开发面板不能证明稳定提升。
- 到达决策或时间上限即保存停止，不续费、不自动续时。完整轨迹、配置、模型、Adam/RNG
  与累计计数保持可恢复；恢复仍使用原截止时间。

## 运行与报告

```bash
# SOURCE_RUN 是已完成 B 组所在目录；NEW_RUN 必须是新目录。
.venv-train/bin/python -m boardbench.families.reward_prepare \
  --source "$SOURCE_RUN" --output "$NEW_RUN" --source-commit "$COMMIT"

# 使用已核实的远端分配、冻结源码及原始配置运行。
.venv-train/bin/python -m boardbench.families.pool_training \
  --config "$NEW_RUN/runs/harmonies/aux/config.json"

# 只读更新各条件进度、配对胜率差与分项差异。
.venv-train/bin/python -m boardbench.families.reward_report "$NEW_RUN"
```

`reward_report.json` 保留原始判断依据及比较双方的实际训练决策量；环境 seed 相同不意味着
训练量完全相同。运行配置、机器清单、启动脚本、轨迹和权重仅存放在忽略的输出目录。

实现验证和实际启动状态另见本目录的启动记录；本文描述协议，不作为效果提升证据。
