# Harmonies 成功经验复盘与双人环境族能力审查

2026-11-01。检查基于 `94ec98f` 的代码、历史原始结果和本轮实际对手配置。
本文记录已完成的审查与下一轮设计；没有修改游戏、网络、训练奖励或部署策略。
范围为当前 16 个合格双人配置；Five Tribes 仍为研究状态，不新增能力认证。

## 主要结论

1. 旧 Harmonies 的强模型建立在丰富的局面表示、真实整局回报和持续 PPO 上。
   专家初始化明显提高起点，部分方法改善早期学习；现有对照不支持把最终实力主要归因于模仿。
2. 目前统一网络输入的是人工压缩的候选特征。Harmonies 的动物图案、摆放位置等关键关系
   没有进入这个 actor；多数其他任务也丢失了牌组、几何或组合关系。调整 reward 无法补回未输入的信息。
3. 当前 16 个评测对手池都没有在线多步搜索。CEM 是离线调启发式权重，不能当作强 rollout 对手。
   当前成绩证明的是对这些固定对手的表现，尚不足以标定游戏中的强策略水平。
4. 应沿两条线改进：让统一学习框架接收足够的玩家可见信息；建立经过验证的强搜索参考。
   搜索本身也要接受预算曲线、候选覆盖、后续策略和新环境检验。

“环境正确”“模型看到了足够信息”“参考对手足够强”是三个不同验收项。
这次已发现输入压缩的具体限制，没有发现足以据此断言游戏规则错误的证据；也没有声称已消除所有限制。

## 1. Harmonies 的能力怎样提升

### 早期对照：模仿提高起点，PPO 贡献很大

下表取 V127/V129 原始 `results.json`，各方法两个训练副本取平均，均为同一组
32 个开发环境、普通开局、贪心纯模型、完整自然终局。列中动作数是每个副本的累计在线动作，
完整 batch 会略超目标；不是专家生成成本，也不是全部试验合计。

| 初始化／训练方式 | 在线训练前 | 累计约 200 万动作 | 累计约 1000 万动作 |
|---|---:|---:|---:|
| 硬动作 BC → PPO | 53.00 | 76.50 | 96.20 |
| 搜索候选软标签模仿 → PPO | 57.05 | 82.83 | 96.73 |
| BC → PPO，早期衰减模仿约束 | 53.00 | 75.77 | 99.34 |
| 随机初始化 → PPO | 27.72 | 73.05 | 98.66 |

软标签组在这个早期面板上有样本效率信号，随机初始化经过充分 PPO 也达到很接近的水平。
两个副本和开发面板不足以宣布某种初始化最终显著更强。
V129 报告中的 `initial` 是约 620 万动作迁移时的模型，**不是零训练起点**；本表起点取自 V127。

共同学习条件是：1346 维局面、256×256 MLP、240 个语义明确的动作、合法 mask；
每批 128 局完整 on-policy 轨迹，gamma=1、GAE lambda=.95，真实分数增量/150，
不额外奖励动物数量。策略随机采样训练，贪心评测。未训练 critic 先用当前策略的真实回报预热。
旧版 FP64 是数值稳定性的历史选择，不是已证明的涨分技巧。

证据：[V127 方法](../V1_2_7_ONLINE_RL.md)、[V129 续训与加速](../V1_2_9_NATIVE_CONTINUATION.md)。
原始表位于本地 `outputs/v127/ppo_a218_20261020_a/results.json` 与
`outputs/v129/ppo_native_a218_20261020_a/results.json`，不随 Git 发布。

### 搜索的有效先验与模型的后续进步

- **候选与后续策略有用。** V125 混合地形／habitat 根候选，再用 habitat 模拟到终局；
  同 12 个开发环境、每局累计 900 秒，均分 117.42 对 106.83。它是小样本自适应开发结果，
  不能当独立泛化结论；但说明“考虑什么、后续怎样玩”比单纯堆重复模拟更值得检查。
  [V125 结果](../V1_2_5_RESULTS_20261020.md)
- **继续学习有效，但后半程不轻。** V132 在同一批 512 个新确认环境上，从 105.41 提升到
  107.50，配对差 +2.08，描述区间 `[1.16,3.01]`。该探索共 248 次试验、约 9.93 亿新增动作，
  账本为 356.01 CPU 核时和 22.08 物理 GPU 小时；大量分支未产生进步。
  [V132 结果](../Harmonies_V132_Autonomous_Model.md)
- **独立 critic 有小幅正信号。** V133 各副本新增 2000 万动作，在同一 512 确认面板，
  普通 PPO 两副本均分 108.10，独立 critic 108.70，差 +0.60，环境区间 `[0.02,1.18]`；
  自模仿为 108.05。只有两个训练种子，不能据此认定普适优势。
  原始证据：本地 `outputs/v133/continuous_a226_20261021_a/confirmation.json`。
- **最终单人交付达到 112.18。** V138 冻结模型在新 512 局完整验证得到该均分；
  另外 32 局限时子集全部完成，平均在线决策耗时 0.454 秒/局。
  这些是不同面板，不能把各版本绝对均分直接相减为方法贡献。
  [V138 交付](../Harmonies_V138_Delivery.md)

加速让足够多的在线学习和对照变得可承受。V129 在等价更新检查下，端到端 PPO 批次吞吐
提高 25.9%；它没有改变策略可见信息或游戏语义。应迁移这类等价优化及资源记账方法，
不能把编码微基准或 GPU 利用率直接当成策略进步。

### 不应作为“已成功配方”照搬的部分

- **教师后续与学生后续错配。** V131 的 768 个状态诊断中，教师建议由 habitat 续玩时
  平均 +1.83 分，交回学生续玩时 −0.81 分；过滤后的完整对局没有稳定优势。
  教师的 Q 不能直接作为学生 critic 的无偏目标。
  [V131 结果](../V1_2_11_CONTINUATION_GUIDANCE.md)
- **会完成目标不等于整局更强。** V137 联合训练的局部目标完成率 70.83%，对照 35.42%；
  同面板整局均分却是 112.00 对 112.10。只学目标选择、刷新目标标签也未胜过继续 PPO。
  [V137 结果](../Harmonies_V137_Goal_Selection.md)
- **双人迁移存在真实规则／分布差异。** 不能要求单人 112 分直接成为正式双人的目标。
  V147 保留的双人纯 RL 在其固定对手、512 新环境换座确认中为 86.17 分，父模型同面板
  85.29；后续独立 V150 面板为 85.64。V150 改进动物能力但损失地形，总分没有确认提升。
  [双人学习协议](../Harmonies_V147_Search_to_RL.md)、[阶段总结](../Harmonies_Stage_Summary.md)

因此，值得迁移的是可验证的能力链：充分表示 → 合理起点或有用示范 → 真实完整对局 PPO →
足量采样与同起点对照 → 独立确认。目标层、技能层和新辅助损失应作为消融，不能预设有效。

## 2. 当前统一框架到底缺在哪里

旧版单人编码显式包括每格堆叠、动物占位、资源市场、待放资源、持有卡与完成进度、动物卡
图案相对坐标、需求堆叠和计分轨道。双人编码还覆盖两个棋盘、全部市场槽位和终局阶段。
见 [单人编码](../../src/boardbench/v12/encoding.py)、
[基础棋盘特征](../../src/boardbench/environments/numerical.py)、
[双人编码](../../src/boardbench/v140/encoding.py)。

当前 [候选网络](../../src/boardbench/families/neural.py) 的输入是每个动作的 24 维手工特征。
actor 分别处理各候选，没有独立的完整局面编码；critic 只对这些候选编码做均值／最大池化。
冻结启发式 logits 继续加在 actor 残差上，并有 prior-KL 约束。它们可能限制探索，
但残差理论上能够克服先验，不能仅凭存在 prior 就断言模型被锁死。

Harmonies 的 [特征实现](../../src/boardbench/families/harmonies_kernel.py) 只使用前 9 个位置，
其余 15 个始终补零：启发式标量、5 种动作类型、持牌数、完成卡数、回合数。
拿牌的启发式会读取该卡图案，放资源的特征却主要是地形边际收益；没有显式保留具体卡、
落点或地形与持卡图案的关系。环境原始观察包含这些信息，但网络没有收到它们。

一个可达局面验证：诊断 seed `817230001`、持有 31 号卡时，69 个合法放资源动作只产生
2 种特征向量，最大一组含 46 个动作。相同特征和相同 prior 必定得到相同 actor logit，
增加 critic 标签或训练步数不能让该结构有条件地区分这一组动作。
其中可能包含对称等价动作；这个检查证明信息合并，不证明每一处合并都降低得分。

当前 V171 已经采完整对局，也使用 actor-critic；这两点不需要重新发明。
它仍与旧强模型在表示、目标和训练量上不同：终局胜负／混合效用不等于旧单人真实分数增量；
本轮 Harmonies 每分支最多新增 50 万动作，也不是旧路线每分支累计 1000 万动作的等预算复现。
当前模型另有祖先训练成本，不能把 50 万当作全部训练量。

## 4. 现有“搜索对手”究竟是什么

逐一读取本轮 16 个 `runs/<game>/win/config.json` 的实际 `panel`，并核对
[策略工厂](../../src/boardbench/families/play.py)：

| 对手来源 | 当前涉及任务 | 决策方式 |
|---|---|---|
| `initial_common`、`heuristic` | 全部 16 个 | 同源初始 RL；手工特征贪心 |
| `cem_*` | Cascadia、两款 Century、Clever、Dominion、El Dorado、Gizmos、Jaipur、Stone Age、Targi、Toy Battle | 离线优化 24 个线性权重，在线特征点积；不是逐动作多步模拟 |
| 历史 `ppo_*` | Calico、Machi Koro、Patchwork、Splendor | 同一紧凑表示路线的旧 RL |
| `retained_rl` | Harmonies | 旧专用双人 RL，包含其规划器；不是高预算 rollout |

因此应把旧比较称为“相对当前启发式／策略池”，不要泛称“超过搜索”。
搜索未参与这个 panel，当前不能断言这些策略已经很强，也不能仅凭结果直接断言搜索一定更强。
需要实际建立更强、不同方法来源的参考。对手种类和生成成本应写入 benchmark 的结果卡。

Harmonies 已有一个直接的正式双人例子：V146 在同 16 个新开发环境、换座对固定对手时，
每局累计 900 秒的终局 habitat 搜索为 **98.75 分**，纯模型为 **82.88 分**；动物分分别
44.91 和 12.19。总分配对差 +15.88，描述区间 `[8.32,23.43]`。
这证明当时存在一个明显更强的高预算参考，但仍是固定对手的小开发面板，
不能把这个差值直接套到今天的模型或其他游戏。
证据：[V147 的同面板起点记录](../Harmonies_V147_Search_to_RL.md)。

## 5. 统一方法怎么改，如何避免重复旧问题

### 输入验收优先

共用一个训练／评测框架，各任务提供版本化 `encode_observation` 与 `encode_action`：

- 局面编码保留合法可见的棋盘／手牌／市场／阶段／对手公开进度；动作编码保留位置、目标牌、
  支付、数量、方向和动作类型。先用紧凑数值张量＋mask／MLP，不要求先搭大型 Transformer。
- actor 同时接收局面上下文和候选动作；critic 直接读局面。启发式评分作为额外输入或可退火
  prior，不能是唯一信息来源。静态组件表可共享，决策 seed 和私有 snapshot 不进入网络。
- 为每款游戏设计重要信息改变而原特征不变的见证；检查新编码是否保留这项差异。
  单纯增加 action ID 只能打破同局平局，不能解决跨局面的语义信息缺失。
- 修改隐藏牌序／对手未知手牌时，玩家输入必须不变；修改本方合法可见的重要状态时，编码
  应保留差异。验证动作重排等变性、mask、座位变换、阶段覆盖和实际非零梯度。

表示更丰富的收益目前是有代码依据的假设，不是已完成的性能消融。
旧权重、特征版本和成绩保留；新编码要用新模型格式，不能直接把旧权重当作兼容加载成功。

### 强搜索参考的验收

复用 Harmonies 的经验，不要求所有游戏都套同一种 MCTS：

1. 先验证候选覆盖和合法多步模拟；多个启发式提供有区别的候选／后续策略。
2. 以真实终局效用或经过检验的 value 评估；局部形状分／引擎分不能冒充真实胜负。
   计分型游戏可同时保留自身总分搜索与胜负搜索，分别标明优化目标。
3. 有隐藏信息的游戏从玩家观察和可见历史构造一致的可能状态，不能直接 clone 真实私牌／
   未来 RNG。模拟中的双方也按各自可见信息行动；信息集采样的近似偏差需要披露。
4. 开发初筛可用 4 个共同新环境、两座位，在每玩家每局累计 **30／180／900 秒**下比较。
   这些是拟定档位，不是本轮已启动预算。无收益时检查候选、评价和后续玩家，不直接加时间。
5. 有希望的方法扩到 16–32 个共同新环境并重复搜索随机性，分别对旧启发式、旧 RL 和
   不同搜索对手评估。512 环境可用于快速纯模型确认；不能把其均分与不同 32 局搜索均分当配对差。

仅上述 16 游戏×4 环境×2 座位×三个预算，单个冻结对手、单次搜索重复的 solver 预算
合计约 **39.47 CPU 核时**；没有包含模拟器外层、教师开发、复测、失败与保存开销。
它是预算算术，不是实测耗时或已获得的训练授权，不据此自动启动新批次。

高预算参考用于估计能力缺口；正式部署另以相同在线计算上限公平比较。
每个结果同时报告每局累计决策时间、最大单步时间、模拟步数、完整率、先后手、胜率、
官方总分及分项。不能因为一方推理便宜而称低分更强，也不能隐去另一方的搜索开销。

### 从强参考迁移到统一 RL

先保留同起点继续 PPO 作为对照，再分开测：补充局面／动作表示；减少固定 prior 约束；
强参考初始化或短序列辅助；真实得分／胜负目标。避免一次同时改四项而无法解释收益。

教师轨迹保存真实执行动作、玩家观察、合法 mask、实际剩余回报、数据来源与预算；
候选 Q 单独带后续策略身份／样本数，未评估动作标缺失。
有条件时补学生访问状态，并用学生续玩验证教师建议是否可兑现。
完整轨迹的 BC／价值学习与 on-policy PPO 分开，不能把旧专家轨迹直接当新 PPO 数据。

计分任务可测试先学自身得分、再优化胜负的课程，但不能改变正式比较目标。
Jaipur 的整场印章、Machi Koro／El Dorado 的竞速、Toy Battle 的直接获胜条件必须各自保持。
能力提升以正常开局整局结果为准，局部完成率／预测 loss 只作诊断。

## 6. 建议的推进顺序和当前交付边界

先恢复 Harmonies 在统一框架下利用完整信息的能力，旧正式双人 RL 和强 rollout 都作为锚点；
同时选择 **Gizmos、Dominion** 覆盖引擎连锁和牌组规划。通过后将同一套编码验收、训练对照和
教师接口推广到上表其他任务；按几何、资源规划、竞速／战术分组实现具体特征与搜索。
所有任务遵守相同验收方法，Harmonies 的作用是有现成强参考可快速识别退化。

新模型至少用两个训练种子、相同开发环境与先后手配对比较，同时报告动作数、完整局数和
端到端成本；冻结候选后才用新确认集，正式 test 不参与。只有在独立完整对局上有收益才晋升，
保留高分、快速和互补策略。教师生成成本计入策略开发成本，后续 benchmark 还需明确它是
提供给所有 agent 的公共先验，还是某次开发预算内自行获得的数据。

本次已完成历史复盘、16 项代码／对手配置检查、可达局面诊断和定向回归。
输入结构升级和其他 15 款游戏的强搜索尚未实现；当前结果应继续标为启发式／同源 RL 参考池，
除已有独立证据的模型外，不能用本次审查把它们重新标为强基线。旧批次未被中断或扩预算。
